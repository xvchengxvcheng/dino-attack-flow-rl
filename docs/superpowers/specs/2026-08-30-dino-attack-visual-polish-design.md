# Dino Attack 第二轮场景视觉精修设计

**日期：** 2026-08-30

**状态：** 已实施并完成 A 镜头/暖中性环境光/外围远山修订；等待 TASK-8.11 Task 10 后续冻结

**目标场景：** `dino-attack/Assets/LlamAcademy/Dinos/Scenes/Dinos.unity`

**实施时机：** 本规格可与 `TASK-8.11` 并行完成文档准备，但 Unity 实施必须在 `TASK-8.11` 场景安装完成并交出 Editor 独占权后开始。本文不为该工作抢占新的主计划编号；批准实施计划时再把它登记为 `TASK-8.11` 之后的下一项视觉精修任务。

## 1. 背景与目标

现有场景已经完成第一轮暖色 Low-poly 热带峡谷改造，并保留五区四边形、地表速度、房屋、六选三城墙、守卫、单局重启和 Human/AI 同场景协议。第二轮不重新设计地图或玩法，而是在现有结构上提高整体构图、光照层次、地表统一性、村庄完成度、远景轮廓和 UI 质感。

最终视觉方向为“高完成度、风格化 Low-poly 热带峡谷战场”：晴朗金色午后、暖色主光与暖中性环境补光、清晰但不过黑的阴影、暖赭石峡谷、自然青绿色浅水、村庄作为画面焦点。目标平台按高性能 PC 视觉优先处理，Human 模式允许更高密度的纯视觉装饰。

## 2. 硬性边界

### 2.1 必须保持不变的玩法事实来源

- Z1–Z5 的 A/B/C/D 顶点、面积、间隙、Trigger、部署合法性和严格 `(u,v)` 映射。
- 石路、草地、泥地、坡地和浅水的速度倍率 `1.10/1.00/0.85/0.80/0.70`。
- 所有 NavMeshSurface、NavMeshData、NavMeshAgent 参数、可达性和公共空间。
- 八栋房屋的玩法根、Collider、生命、目标选择、死亡占地和肉返还语义。
- 六个墙位、每局六选三、城墙与墙上守卫的 Transform、生命、攻击和生命周期。
- 每局 `3 Archer + 2 Mage` 地面守卫、恐龙目标优先级、攻击范围、胜负和 Restart 行为。
- Camera bounds、Home 复位和现有 RTS 镜头控制语义。
- `TASK-8.11` 冻结后的五流 observation、4D action、奖励、50 秒自然终止、terminal/truncated、Agent ID 和训练启动协议。
- Human 与 AI 加载同一个 `Dinos.unity`；视觉优化不得创建训练专用玩法地图分支。

### 2.2 明确不做的内容

- 不新增部署尘土、命中闪光、死亡消散、脚步灰尘、浅水水花或其他战斗 VFX。
- 不改变血条的出现、隐藏、选中、受伤或交战逻辑。
- 不改变 UXML 元素名、C# 查询名、回调、热键、按钮状态、胜负面板和 Restart 流程。
- 不增加 Collider、Trigger、NavMeshObstacle、NavMeshModifier、NavMeshModifierVolume、Agent、攻击遮挡或玩法脚本到视觉对象。
- 不增加地貌伤害、掩体、LOS、交互水体、反射摄像机、折射、Scene Color 或运行时地形位移。
- 不修改 Packages、ProjectSettings、算法实现、训练配置、checkpoint 或历史验证产物。
- 不设置固定分辨率或固定 FPS 作为完成门槛。

## 3. 分层架构

### 3.1 冻结玩法层

冻结层包含 Terrain Surfaces、五区 Trigger、Session Defense Layout、Village House gameplay roots、城墙与守卫根、NavMesh、Camera Bounds、RoundManager、部署服务和正式 Training 根。实施前对这些对象记录稳定路径、关键组件、Transform 和协议哈希；实施后逐项比对。

美术实施不得移动、缩放、旋转、重父级或禁用冻结对象。若画面需要改变房屋、城墙或地貌外观，只能修改其独立视觉子层或增加无玩法组件的子节点。

### 3.2 可修改视觉层

优先扩展现有 `/World/Open Tropical Battlefield/Art Pass`，并保持以下职责边界：

- `Lighting & Atmosphere`：主光、环境补光、雾、天空和后处理。
- `Terrain Dressing`：纯视觉地表覆盖、边缘过渡、石块和植被。
- `Village Details`：房屋视觉子层、道路边缘、围栏细节和村庄道具。
- `Canyon Rim & Distant Scenery`：峡谷轮廓、远山和画面边界。

不创建新的 `VFX` 职责根。任何现有粒子或特效保持原状，不作为本轮交付内容。

### 3.3 确定性构建与验证

视觉布局继续由确定性 Scene Builder 生成或修复，不直接编辑场景 YAML。随机感只能来自固定 seed、有限候选表和离散旋转/比例档位。Validator 必须能够独立证明视觉层没有玩法组件，并在任何场景保存前报告违规对象的完整层级路径。

## 4. 视觉设计

### 4.1 光照与氛围

- 时间氛围为晴朗金色午后，不采用黄昏、夜景或强烈戏剧性逆光。
- 主方向光使用暖金色，形成清楚的单位、房屋和岩壁投影；2026-08-30 用户复核已把冷蓝灰环境光取代为暖中性补光，避免房屋和守卫出现蓝色覆层。
- 天空保持明亮青蓝，并通过远景雾把峡谷轮廓从战斗层分离；雾不能吞没 Z1–Z5 或村庄边缘。
- 后处理只用于整体曝光、色彩分级、轻量 Bloom、环境遮蔽和对比控制，不依赖相机抖动、景深或运动模糊。
- 村庄与中央广场是主视觉焦点；峡谷边缘负责框景，不能比战斗区域更亮或更饱和。

### 4.2 地表与浅水

- 保留现有六个 Stage8 地表材质和浅水 Shader 的玩法接线，只调整材质参数、共享纹理、宏观色差与过渡表现。
- 公共地面使用暖土色统一全图，五区通过色相、粗糙度、植被和小型道具形成自然差异，不恢复持续高饱和色块。
- 地貌边界可用纯视觉贴花式覆盖、碎石、草簇或材质过渡弱化直线感，但不得误导实际部署边界；部署时仍以现有 Presenter 为准。
- Z3 保持空战斗面：四边形浅水区内不新增桥、河石、泥边、植物或其他可见物体。只优化水色、透明度、流动尺度和河床层次。
- 水体保持平静的自然青绿色，不加入水花、涟漪交互、反射摄像机或折射。

### 4.3 村庄、房屋与城墙

- 八栋房屋的玩法根和占地完全冻结；只调整既有 Tribal Hut 视觉子层的材质统一、比例观感和无碰撞附属细节。
- 村庄通过道路边缘、木桩、篮筐、木桶、旗帜、草簇和少量石块增强生活感，所有新增对象均为纯视觉且不遮挡战斗单位。
- 装饰密度由中央广场向村落外缘递减，在主要通路、城墙前方、守卫射击方向和房屋血条附近保留清晰负空间。
- 城墙只允许增加不带玩法组件的视觉附件；不得改变墙位根、墙体命中体积、墙上弓箭手位置、30 米索敌或血条锚点。
- 房屋死亡后既有 `3–5` 根木梁和隐藏占地语义保持不变；不新增废墟碰撞或阻挡。

### 4.4 峡谷 Rim 与远景

- 继续使用暖赭石、暗褐阴影和浅橙受光面的 Low-poly 岩壁语言。
- Z1、Z5 后方两座大山保持在部署区之外，只优化轮廓和材质，不移动其玩法相关对象，也不恢复 Barrier。
- 2026-08-30 用户的 A 镜头复核取代额外五座外围远山：`Canyon Rim/Distant Scenery` 保留为空的职责根，不再实例化 far west / north-west / north / north-east / far east 五个剪影；既有北侧 Rim 主体继续承担画面边界。
- 所有新增远景对象为 0 Collider、0 NavMesh 组件、0 gameplay MonoBehaviour，不投射会遮黑主战场的大面积阴影。

### 4.4.1 A 镜头修订

- Home 目标对齐战场中心 `(-3.5,-2.5,-12)`，透视 FOV 为 `58`，FollowOffset 为 `(0,82,38)`，形成更居中、更俯视且减少外围空白的全场构图。
- 滚轮 `ZoomSensitivity` 从 `0.12` 提高到 `0.22`；最小/最大缩放 `0.45/1.35`、边界、Home 复位和其他 RTS 输入语义保持不变。

### 4.5 UI 视觉精修

- 只修改布局间距、面板尺寸、字体层级、描边、底色、按钮外观和信息密度，不修改行为。
- 色彩统一为暖木、炭灰、沙金和低饱和提示色；减少大面积不透明面板遮挡地图。
- 食物、选择、部署反馈、Start、Victory、Defeat、Restart 和现有血条行为全部保留。
- 小分辨率只要求信息不重叠和按钮可用；本轮不重新运行四分辨率视觉矩阵，也不以某个固定分辨率作为硬门。

## 5. Human 与训练模式

- Human 模式启用完整高密度视觉层，包括地表装饰、村庄细节、远景、灯光和后处理。
- `--dino-training` 继续由 `TASK-8.11` 的启动逻辑按组件关闭 Renderer、Light、Volume、ParticleSystem 和音频；视觉根的关闭不得停用其父级中的 Collider、Trigger、NavMesh、Agent、RoundManager 或部署组件。
- 本轮不新增训练模式专用玩法对象。新增视觉对象即使未被启动器识别，也必须因归属 Art Pass 和无玩法组件而可以安全整体禁用。
- 记录视觉修改前后的同条件 Human 模式帧时间，以及无渲染训练吞吐，仅用于发现明显异常；不设置固定 FPS、分辨率或吞吐数值作为验收门槛。

## 6. 与 TASK-8.11 的并行和交接规则

### 6.1 当前可并行范围

- 设计规格、实施计划、资源清单、材质参数表和验收清单。
- 项目外概念图或参考图，不复制进 Unity `Assets`。
- 只读检查，不打开第二个 Unity Editor，不运行导入、编译、测试、构建或场景保存。

### 6.2 Unity 实施交接

1. `TASK-8.11` 完成 Task 4 的正式 Training 场景安装并记录安装后场景哈希。
2. 当前执行 `TASK-8.11` 的任务暂停所有 Unity 写入并明确交出 Editor 独占权。
3. 视觉任务记录自己的基线哈希与冻结玩法清单，再独占 Unity 完成美术实施。
4. 视觉任务完成编译、Validator 和玩法隔离检查后交还 Editor。
5. `TASK-8.11` 再运行 Task 10 的最终 Player、20 次重载和四环境验证，并以包含最终视觉层的场景生成统一冻结哈希。

若无法安排上述暂停/交接，则采用更保守的顺序：先让 `TASK-8.11` Task 10 完成，再启动视觉实施并单独重新冻结。任何情况下都禁止两个任务同时保存 `Dinos.unity`、运行 Unity 导入或修改同一 Builder/Validator/UI/Volume/材质文件。

## 8. 验证与退出标准

### 8.1 玩法隔离硬门

- 视觉根下启用的 Collider、Trigger、NavMeshObstacle、NavMeshModifier、NavMeshModifierVolume、NavMeshAgent 和 gameplay MonoBehaviour 数量均为 `0`。
- 五区 A/B/C/D、Trigger、地表类别、速度、部署映射和公共空间拒绝结果与交接基线一致。
- 八栋房屋、六个墙位、三面会话城墙、墙上守卫和地面守卫的玩法根 Transform 与关键组件保持一致。
- 15/15 恐龙/区域 NavMesh 路径继续通过；攻击、胜负、Restart 和 50 秒自然失败语义无变化。
- `TASK-8.11` 五流 shape/order、4D action、BehaviorParameters、奖励和 terminal/truncated 协议完全一致。
- Human UI 的元素名、查询、回调、热键和状态行为不变；血条显示逻辑不变。

### 8.2 视觉完成硬门

- Home 与常用运行镜头中，村庄是明确焦点，五区可辨认，Rim 和远景具有自然层次。
- 主光、阴影、天空、雾和后处理形成统一金色午后氛围，阴影区域仍能辨认单位和地貌。
- 地表无明显纯色调试块、粉色材质、破损 Shader、闪烁或透明排序异常。
- Z3 内部仍为空战斗面，水体自然但没有新增 VFX 或交互效果。
- 村庄和远景装饰提高完成度，同时主要通路、城墙前、单位群和血条周围保持可读。
- UI 视觉统一且减少遮挡，但所有现有交互与状态保持原样。

### 8.3 最小验证集合

- 一次 Unity fresh compile 和 fresh Console error 检查。
- 一次 Builder/Validator 与视觉组件审计。
- 一次聚焦的五区、15/15 导航、部署、攻击、胜负/Restart、协议回归集合。
- 一组同相机、同画质、同运行状态的 before/after 截图和帧时间记录。
- 一次无渲染训练启动/吞吐对比，确认视觉层关闭且无明显异常。
- 连续两次 canonical builder byte-stable，最终统一记录 scene、material、shader、resource 和 Player/protocol 哈希。

不恢复与本次改动无关的完整 Unity suite、四分辨率矩阵、固定 FPS 门槛或正式长训练。

## 9. 失败恢复

- 新增内容只进入 Art Pass 或隔离的项目侧视觉资产目录；禁用视觉根即可保留全部玩法。
- Builder 在任何视觉违规时必须在保存场景前失败，不允许“先保存再修复”。
- 若地表、房屋或 Rim 修改改变 NavMesh、部署、攻击或训练协议，立即停止视觉调优，恢复到交接基线的玩法层引用和 Transform，再重新验证。
- 若后处理、透明水面或高密度装饰造成明显异常，按“后处理强度 → 装饰密度 → 水面复杂度”的顺序降级；不通过修改玩法对象或训练设置换取性能。
- 不使用 Git reset、checkout、clean 或覆盖用户 dirty 文件作为回退方式；只撤销本任务新增的视觉引用或由确定性 Builder 重建本任务视觉层。
