# Dino Attack 第二地图“分层战场”设计

**日期：** 2026-08-30  
**对应阶段：** 阶段 8 / 第二地图与双地图玩法接入  
**状态：** 对话设计已批准，等待用户复核本文  
**事实来源：** `docs/PROJECT_PLAN.md`

## 1. 背景

第一张正式地图 `Dinos.unity` 已形成开阔热带战场、五个四边形部署区、房屋返肉和单局50秒玩法。第二张地图不通过新增美术包或显著改变岛屿外貌建立差异，而是在完全复用第一张地图资源与玩法系统的前提下，提供低初始资源、分层房屋、防御层级和受控随机布局。

第二张地图与第一张地图使用同一个端到端模型。多地图输入遵循已批准的 `dino_attack_structured_set_v2`：动态 Regions 和唯一 `RoundManager.DinoTarget` 坐标使模型直接观察当前 episode 的真实区域与目标几何，不增加 map one-hot。

## 2. 目标

1. 新建独立正式场景 `LayeredBattlefield.unity`，玩家显示名为“分层战场”。
2. 全部模型、Prefab、材质、纹理、Shader、音效、UI视觉和环境装饰复用第一张地图已有资源，不导入新的美术资源包。
3. 以 `50` 初始肉形成“外围取得资源—中层突破—核心进攻”的玩法节奏。
4. 改变 Z1–Z5 的位置，但保持区域 ID、地貌类型、速度倍率和4D动作语义一致。
5. 每局从有限且预先验证的候选布局中按 seed 产生中度随机变化，不在运行时重建 NavMesh。
6. 玩家完成一局后，可让默认 AI 模型在同一地图、同一布局 seed 下重赛，并显示玩家/AI对比结果。
7. 第二张地图完成后，正式训练按 episode seed 在两张地图之间 `50%/50%` 采样。

## 3. 非目标

- 不把第二张地图做成新的视觉主题、海湾/河网景观项目或新资源导入任务。
- 不增加 map ID、地图尺寸、地貌倍率或防御倍率观测。
- 不改变 v2 六流270标量、4D动作、奖励函数、50秒自然失败或恐龙战斗/目标优先级。
- 不进行任意连续的房屋/墙位置程序化生成，不在每个 episode 重烘焙 NavMesh。
- 不把默认 AI 重赛接入外部 Python 进程，也不在观看模式更新模型。
- 不用启发式策略伪装缺失或不兼容的默认模型。

## 4. 场景与资源边界

### 4.1 正式场景

- 地图1：`Dinos.unity`，显示名“开阔战场”。
- 地图2：`LayeredBattlefield.unity`，显示名“分层战场”。
- 菜单：新增轻量 `MapSelect.unity`，展示 Dino Attack Logo 和两张地图入口；点击任一地图立即创建 Human 启动请求并进入对应场景，不再保留独立“开始”按钮。

两张正式地图使用相同世界原点、X `[-55.5,48.5]`、Z `[-53,29]` 固定边界以及相同相机/单位尺度。地图2可以重新排列五区、房屋、墙、守卫与唯一目标，但不得越出固定范围。

### 4.2 资源复用

地图2只引用地图1已经存在的房屋、墙、Archer、Mage、恐龙、岩石、植物、废墟、地表、水面、VFX、音效和UI资源。允许创建地图2专用的场景对象、布局配置、候选点数据、NavMeshData 和 ScriptableObject 配置；这些是场景/玩法数据，不是新的美术来源。

两张地图保留可见的共享基础地面，浅水区统一使用 `ShallowWaterTeal` 水面材质；地图1和地图2都不生成独立 Riverbed 层。Dino Attack Logo 仅在 `MapSelect.unity` 显示，不出现在两张玩法地图中。

共享玩法代码不得复制成地图2版本。地图差异通过场景配置、候选布局和启动上下文表达。

## 5. 分层玩法

### 5.1 固定规则

- 初始肉：`50`。
- 单局时限：50秒模拟时间。
- 房屋死亡：每栋继续一次性返还 `100` 肉。
- 胜利：恐龙进入当前场景唯一 `RoundManager.DinoTarget` 对应目标范围。
- 失败：50秒到期或恐龙全部死亡。
- 恐龙成本、攻击、移动、目标类别优先级、地貌速度和奖励均沿用正式共享规则。

初始 `50` 肉允许部署1只迅猛龙或2只肿头龙，不能直接部署霸王龙。地图通过外围低耐久房屋提供第一轮资源，再让玩家/AI扩大阵容。

### 5.2 房屋层级

地图固定存在8栋房屋：

| 层级 | 数量 | Tier / HP | 返肉 |
|---|---:|---|---:|
| 外围 | 2 | Tier 1 / `100` | 每栋 `100` |
| 中层 | 4 | 2栋 Tier 2 / `150`，2栋 Tier 3 / `225` | 每栋 `100` |
| 核心 | 2 | Tier 4 / `325` | 每栋 `100` |

中层四栋房屋每局在本层候选位置间随机分配两栋 Tier 2、两栋 Tier 3；不得把外围启动房屋升级为高 Tier，也不得把核心房屋降为启动房屋。

### 5.3 防御层级

| 层级 | 地面弓箭手 | 法师 | 墙 | 墙上弓箭手 |
|---|---:|---:|---:|---:|
| 外围 | 2 | 0 | 0 | 0 |
| 中层 | 1 | 1 | 2 | 2 |
| 核心 | 2 | 2 | 1 | 1 |
| **合计** | **5** | **3** | **3** | **3** |

每面墙继续恰好附带1名墙上弓箭手。地面守卫共8名，墙上弓箭手3名，正好填满 v2 Guards `(11,7)`；不增加新兵种列或第12行。

外围两名弓箭手分别看守两栋 Tier 1 启动房屋，但外围不设墙。中层形成两侧突破防线，核心保留最高密度压力。

## 6. 五个部署区

地图2改变五区位置，采用“成对资源区、成对突破区、中央高风险区”的结构，但部署后恐龙仍通过同一 NavMesh 自由机动，不形成五条固定路线。

| 区域 | 地貌 | 速度 | 地图2玩法角色 |
|---|---|---:|---|
| Z1 | StoneRoad | `1.10x` | 西侧快速资源区，接近一栋外围 Tier 1 房屋 |
| Z2 | Grass | `1.00x` | 西侧稳定突破区，接近一面中层墙 |
| Z3 | ShallowWater | `0.70x` | 中央高风险区，世界距离较短但移动慢、守卫压力高 |
| Z4 | Mud | `0.85x` | 东侧泥地突破区，提供不同侧翼代价 |
| Z5 | Slope | `0.80x` | 东侧坡地资源区，接近另一栋外围 Tier 1 房屋 |

Z1/Z5、Z2/Z4 在几何角色上成对，但速度和风险不要求镜像相等。两图始终保持相同 `ZoneId -> TerrainType -> SpeedMultiplier` 语义，使不观测地貌倍率的共享模型不会面对编号语义反转。

每套区域都必须恰好包含五个严格凸四边形，使用 A/B/C/D 顺序、互不重叠、不覆盖村落内部，并保留公共可通行但不可部署空间。

Home 视角的构图以村落核心位于画面上方、五个部署区位于其下方和两侧为硬性要求。每个当前 preset 的可见地表 Mesh、地貌速度 Trigger、部署合法性与 v2 Regions 观测必须由同一组 A/B/C/D 顶点生成和切换，禁止继续显示另一张地图或另一 preset 的地表资源。房屋的逻辑 Tier 必须确定性绑定对应的 `Hut_Tribal_Tier1–4` 美术，候选数据还必须明确旋转、缩放和落地基准；验证以最终 Renderer 包围盒/占地为准，不能只检查玩法根 Transform。

## 7. 中度随机布局

### 7.1 随机内容

每个地图2 episode 由确定性布局 seed 决定：

1. 从3套已验证的 Z1–Z5 位置预设中选择1套。
2. 两栋外围 Tier 1 房屋分别从本侧候选点选择位置。
3. 四栋中层房屋在固定中层候选位间随机分配2栋 Tier 2和2栋 Tier 3。
4. 两面中层墙从4个中层候选墙位选择。
5. 一面核心墙从2个核心候选墙位选择。
6. 5名地面弓箭手和3名法师仅从各自层级的候选点采样。
7. 唯一 `DinoTarget` 从核心区3个候选位置选择。

固定不随机的内容包括初始肉、单位/墙/房屋总数、房屋层级数量、各层守卫数量、地貌映射、奖励、时限和动作语义。

### 7.2 生成方式

房屋和墙只使用预先烘焙并验证的布局组合，不任意连续移动。候选数据必须包含兼容关系或直接列出合法组合；运行时只从合法集合采样，不通过无界重试寻找可行布局。

五区预设、守卫点和目标点可以在相应预验证集合中变化，但每个组合必须满足：

- 所有对象位于固定地图边界内；
- 五区几何有效且拥有合法部署样本；
- 房屋、墙、守卫、目标、水面与部署区不产生非法占用重叠；
- 三种恐龙从每个区域均有到外围、中层、核心和最终目标的有效 NavMesh 路径；
- 不产生不可见占地、旧 NavMesh 空洞或需要 episode 内重烘焙的状态。

相同 scene、layout seed 和配置版本必须生成相同布局签名；不同 seed 应能覆盖多个合法组合。

## 8. 玩家地图选择与结算操作

`MapSelect.unity` 显示两张地图：

- 开阔战场；
- 分层战场：说明“以50肉起步，突破外围、中层与核心防线”。

玩家点击地图入口后直接进入对应场景的 Human 模式；进入玩法场景后仍由中央 Start 开始首局。选图页使用新 Input System 的 UI 输入模块，不提供独立 Start 或 AI 控制选项。

两张地图的 Ended 面板统一提供四个操作：

1. **重试当前布局：** 当前地图、相同 layout seed、Human。
2. **生成新布局：** 当前地图、新 layout seed、Human。
3. **AI策略：** 当前地图、相同 layout seed、默认 AI 模型。
4. **选择地图：** 返回 `MapSelect.unity`。

“相同布局”通过完整重载场景并复用 seed 重建，不继续使用已经被破坏的运行时对象。

## 9. 跨场景启动上下文

共享 `GameLaunchContext`（具体载体由实施计划决定）至少保存：

- 目标场景稳定 ID；
- layout seed；
- 控制方式 `Human` / `InferenceAI` / `TrainingAI`；
- 是否复用当前 seed；
- 玩家上一局的结算快照；
- 默认模型标识、模型 hash 与协议版本；
- AI inference seed。

上下文不得保存或复用已经死亡/销毁的场景对象引用。每次场景加载后，由当前场景验证配置并消费只属于本次启动的上下文；缺失上下文时玩家构建进入 `MapSelect.unity`，训练构建按显式训练参数进入正式地图。

## 10. 默认 AI 同布局重赛

### 10.1 推理边界

默认模型导出为兼容 `dino_attack_structured_set_v2` 的 ONNX，并由 Unity Sentis在本地推理。初始默认产物优先采用正式 Gaussian PPO Set Transformer 策略，但UI只依赖统一的默认模型配置，不把算法名称写死。

推理适配器必须：

- 使用与训练相同的 Global、Regions、Walls、Guards、Houses、Dinos 六流字段和顺序；
- 每25个 Academy step 产生一次4D动作，并通过共享部署/动作执行路径提交；
- 使用确定性推理输出；相同模型 hash、scene、layout seed 和 inference seed 产生相同动作序列；
- 正常渲染并使用 Human 正常游戏速度，不启用 `--dino-training`、`timeScale=20`、采样器或优化器；
- 自动进入 Running，不显示或接收玩家部署操作。

### 10.2 可行性门

正式 UI 接入前，先验证 v2 Set Transformer actor 可以导出并由当前 Unity Sentis加载，六输入和4D输出 shape 正确，所有使用算子受支持。若失败，优先调整 ONNX 导出图或实现明确的 Sentis兼容适配；不得静默连接外部 Python、改用随机动作或启发式策略。

模型文件缺失、hash/协议/shape不匹配或 Sentis加载失败时，“AI策略”按钮保持禁用并显示简明原因；玩家的其他结算操作继续可用。

## 11. 玩家与 AI 对比

玩家一局结束时保存不可变结算快照。AI同布局重赛结束后并列显示：

- 胜利/失败；
- 完成或终止时间；
- 最终剩余肉；
- 按正式共享奖励规则得到的 episode 总奖励。

奖励值必须来自共享奖励分项或统一计算服务，不在UI中复制另一套公式。对比数据只用于显示，不写入训练 rollout，也不改变 checkpoint 或评估报告。

开始新布局、选择另一地图或开始新的玩家局时，旧对比上下文必须清除，不能跨 seed、地图或模型 hash 比较。

## 12. 双地图训练接入

第二张地图完成并通过场景验证后：

1. 两个正式场景加入训练 Player。
2. 每个自然 episode 边界按确定性地图选择 seed 做 `50%/50%` 选择。
3. 两图使用相同 v2 协议、4D动作、奖励、`gamma=0.995`、决策周期和更新协议。
4. 网络不接收 map ID；当前 Regions、DinoTarget、实体位置/状态和资源共同描述决策状态。
5. 训练和评估分别报告 Map 1、Map 2 与混合结果，不能只报告合并均值。

AI观看模式与训练模式是两个不同运行入口：前者运行嵌入式 ONNX 推理和正常渲染，后者运行外部 `flow_rl`、无渲染并行采样和同步更新。

## 13. 生命周期与错误处理

- 场景、地图配置、五区、唯一目标或候选布局缺失时，在开始 episode 前快速失败并给出具体错误。
- 不合法 seed/版本不得回退到另一地图或随机布局；应阻止开始并保留菜单可用。
- 布局在 episode 开始前一次性冻结；Running 中不移动区域、房屋、墙、守卫生成点或目标。
- 自然终止先提交奖励与终止状态，再开放Human结算UI或安排AI/训练重载。
- 玩家→AI同布局重赛必须比较布局签名；签名不一致时禁止标记为同布局对比。
- AI重赛失败不得损坏玩家快照或阻止返回地图选择。

## 14. 最小必要验证

### 14.1 纯规则

- 相同 seed/配置生成相同布局签名，不同固定 seed 覆盖多个预设和候选组合。
- 每个布局严格包含5区、8房、3墙、8地面守卫、3墙上弓箭手和唯一目标。
- 层级数量、房屋 Tier、守卫分配和区域地貌映射不漂移。
- 所有合法组合无需运行时 NavMesh重烘焙。

### 14.2 场景与协议

- 三套区域预设合法，所有部署区至少有合法点；三种恐龙从每区可到达各层与目标。
- Map 1/Map 2 输出相同 v2 六流 shape；Map 2 Guards 恰好可填满11行且无截断。
- Regions 与实际当前预设四顶点一致，Global目标坐标与当前唯一 DinoTarget 一致。
- 两地图 scene ID、固定边界、资源引用和共享玩法组件通过 validator。

### 14.3 菜单、重赛与 Sentis

- MapSelect 能进入两张地图；四个结算操作分别保持/更换正确的地图、seed和控制方式。
- 玩家→AI重赛的布局签名逐字段一致，AI不会触发新的随机布局。
- v2 ONNX 在 Sentis中加载，六输入/4D输出正确、有限并位于 `[-1,1]`。
- 相同布局/model/inference seed 的AI动作序列一致；缺失或不兼容模型时按钮禁用且其他操作可用。
- 玩家/AI快照按 scene、layout seed、model hash 正确配对，开始新局后无串局。

### 14.4 聚焦集成

- 一次两地图混合运行检查覆盖50%/50%选择、自然终止、场景重载和 v2 shape。
- 不为本任务恢复全量 Unity suite、100-episode正式评估、长训练、分辨率/性能矩阵或无关 Player 回归。

## 15. 实施顺序与依赖

1. 先完成并冻结已批准的 multimap v2 协议；它是动态区域和目标观测的前置条件。
2. 对默认 v2 PPO actor 执行 ONNX/Sentis可行性门。
3. 实现“分层战场”的共享配置、预验证候选布局和独立场景。
4. 实现 `MapSelect.unity`、跨场景启动上下文和四个结算入口。
5. 实现嵌入式默认AI同布局重赛及玩家/AI对比。
6. 将第二张地图加入训练 Player 和50%/50% episode选择，并运行一次聚焦集成。

本文获用户复核后，应使用 `superpowers:writing-plans` 编写独立实施计划。不得直接把地图2、菜单、Sentis和混合训练工作塞入正在执行的 v2协议任务而不重划依赖和验收。
