## 1. 文档关系

本文档取代 `2026-08-28-dino-attack-player-scene-design.md` 中以下旧地图方案：

- “保守式三入口强化”和固定三条战线；
- 连续后方部署带与三个前沿部署袋；
- 六个候选部署场地以及已删除的“雨林空地”；
- 任何依赖掩体、建筑或地貌阻挡攻击的设想。

旧文档中的持续部署、共享部署服务、Human/AI 同场景、资源记账、状态机和双仓库维护原则继续有效，除非与本文明确冲突。实施前需要同步重写阶段 8 计划，不允许继续按旧三路线地图实施。

## 2. 设计目标

把当前由巨型橙色山体包围、前景空旷、进攻方向近似固定的场景改造成一座完整可进入的开阔热带战斗岛：

1. 扩大村落与有效战斗范围，让建筑内部空隙、街巷和中央广场都参与战斗。
2. 不规定三条进攻路线；玩家从部分包围村落的五个区域自由部署恐龙。
3. 让区域特点来自面积、出口、地表、位置和移动绕行，而不是锁区、兵种限制或攻击遮挡。
4. 地表明确影响恐龙速度，并通过通行空间、接敌时间和守卫站位间接影响防御态势。
5. 开局展示完整岛屿和外围景观，同时提供 RTS 式自由平移与缩放。
6. 保持现有 Dino Attack 风格为主体，只使用精选 Kenney 模块补充结构和细节。

## 3. 非目标

- 不设计固定三路、道路航线或强制 waypoint 走廊。
- 不轮换关闭部署区，不使用固定部署槽位，不按恐龙类型限制区域。
- 不把房屋、树木、岩石、围栏或高低差用作攻击射线遮挡。
- 不加入战争迷雾、复杂高度命中、弹道穿透、掩体命中率或伤害减免系统。
- 不把整张地图改造成 Kenney 方格地块，也不使用雪地、科幻炮塔、UFO 或明显温带针叶林作为主体视觉。
- 本设计批准不等于立即修改 Unity；场景实现必须等新计划和验收顺序批准。

## 4. 整体空间结构

### 4.1 地图轮廓

- 实际有效世界边界在现有基础上扩大约 25–35%；最终数值由 NavMesh、镜头可读性和性能基线确定，不直接按单一 Transform 比例粗放缩放。
- 村落位于岛屿中上部，五个部署区从西、西南、南、东南、东形成约 240° 马蹄形包围。
- 北侧保留较窄的视觉背景与防御纵深，不形成第六个部署区。
- 现有巨型山体降为低矮、分段的岛缘与背景岩壁，不能继续占据主要屏幕面积或遮挡村落。
- 河道、浅水、泥地、坡面、低矮岩石、棕榈和废墟自然分隔空间，但不构成预设路线。

### 4.2 村落

村落扩大为四个不规则聚落区，共享中央广场：

- 西北聚落；
- 东北聚落；
- 西南聚落；
- 东南聚落；
- 中央核心广场。

四区之间使用宽窄不一的街巷、石路和开敞节点连接，不建立一条权重明显高于其他方向的“主路”。房屋、院落、摊位和平台之间保留足够宽度，让所有恐龙类型可以进入、转身和交战。

中央广场承载现有胜利目标的玩法语义；现有蛋/目标视觉应移入或整合进广场，而不是在村落边缘另设第二个核心。所有方向最终都能接近广场，但到达方式由实时导航和局部空间决定。

## 5. 五个部署区

五区始终同时开放，所有恐龙类型通用。放置只检查区域边界、地面、NavMesh、单位间距、资源和 UI 阻挡，不检查职业或回合轮换规则。

| 区域 | 相对位置 | 空间特点 | 主要地表 | 预期取舍 |
|---|---|---|---|---|
| Z1 废墟前庭 | 近西侧 | 较小、不规则、破损结构分割空间 | 石路、草地 | 离村落近，但可放面积和展开空间有限 |
| Z2 开阔草地 | 中西侧 | 大面积、障碍稀少、出口宽 | 草地、少量石路 | 易集结和转向，但接近距离中等 |
| Z3 河岸台地 | 最远南侧 | 五区最宽，横跨湿地边缘 | 泥地、浅水、草地 | 容量最大但减速明显，适合多方向展开 |
| Z4 棕榈林缘 | 中东侧 | 树干与小石块形成分散绕行 | 草地、泥地 | 路径变化多，集群容易被地形拆分 |
| Z5 岩石高台 | 近东侧 | 较小、出口有限、有坡面 | 坡地、石路 | 离村落近，但进出和大型单位转身更受限制 |

“雨林空地”已从范围中删除且不替换。棕榈林缘是稀疏、可读的战斗空间，不是密闭雨林房间。

## 6. 地表与移动规则

所有恐龙保留各自基础移动速度，再乘统一的地表系数：

| 地表 | 速度系数 |
|---|---:|
| 石质道路 | 1.10× |
| 草地 | 1.00× |
| 泥地 | 0.85× |
| 坡地 | 0.80× |
| 浅水 | 0.70× |

规则要求：

- 同一地表对所有恐龙使用相同比例，不抹平不同恐龙的基础速度差。
- 地表判定只影响移动速度，不改变攻击距离、伤害、命中率、冷却或受到的伤害。
- 多种地表检测区重叠时必须有稳定优先级；建议按“浅水 > 泥地 > 坡地 > 石路 > 草地”解析，禁止逐帧抖动。
- 离开特殊地表后必须恢复正确的当前地表系数，不允许永久残留减速或加速。
- 视觉材质边界与实际判定边界应基本吻合；玩家不能站在看似草地的位置却受到浅水减速。

地貌对防御的影响仅来自接敌时间、通行宽度、绕行、集群展开与守卫站位，不增加一套隐藏的“地形防御数值”。

## 7. 防御结构与攻击语义

### 7.1 村落防御

- 不建连续环形城墙，采用分散哨点、短围栏、路障和村内防御组。
- 只有军事防御对象可破坏，包括经确认的短围栏、路障、哨点和防御单位。
- 房屋、地形、核心广场、主要岩石和树干保持静态，作为移动空间边界。
- 防御放置使用经过验证的固定候选槽位；每局按确定性 seed 选择一个预设组合。
- 被选中的防御从回合开始即全部生效，不强制阶段式出现。

### 7.2 攻击不受遮挡

保留当前攻击命中语义：进入攻击距离并满足冷却/目标条件后即可攻击，不做 Physics Raycast、NavMesh Raycast 或基于遮挡物的命中取消。

因此：

- 房屋、岩石、树木、废墟、围栏和高低差不会阻挡守卫攻击；
- 同样不会阻挡恐龙攻击；
- 环境物只影响移动、绕行、站位和可部署面积；
- 视觉特效可以穿过环境物，第一版不以此为由改变伤害逻辑。

实现与测试必须删除或否决旧设计中的 LOS、硬掩体和攻击阻挡要求，避免 UI 继续显示“掩体防御”图标。

## 8. 部署可视化与交互

采用“自然地标常驻、部署时显界”：

1. 未选择恐龙时，五区只通过废墟、草地、河岸、棕榈和岩台等自然地标表达，不常亮彩色边界。
2. 选择恐龙进入部署状态后，五区边界同时以低强度显示。
3. 悬停区域提高亮度，并显示区域名称、当前位置地表和速度系数。
4. 合法位置显示预览；非法位置同时显示图标和简短文字原因，不能只依赖红绿色。
5. 取消、部署成功或进入 Ending 后立即清除所有区域边界和预览状态。

世界反馈不显示“攻击被遮挡”或“硬掩体”状态，因为该机制不存在。

## 9. 镜头与游戏视图

- 默认约 55° 斜俯视。
- 开局与 Home 复位采用“完整岛屿视图”：有效战斗区、岛缘和外围景观全部入镜。
- 支持屏幕边缘或键盘平移、滚轮缩放、中键拖动和 Home 复位。
- 镜头边界覆盖完整可进入战斗区，但不允许移动到大面积空白世界外部。
- 外围景观必须控制宽度、高度和密度；巨型山体不得迫使有效战区在默认视图中过度缩小。
- 最小缩放保证完整岛屿可见，最大缩放保证村内单位与部署反馈可读。
- UI 安全区域不得遮挡 Z3 河岸台地、中央广场或部署提示。

完整岛屿入镜会让单位相对变小，这是用户接受的构图取舍；实现阶段通过限制无效外围面积、清晰单位轮廓和快速缩放缓解，而不是改回局部默认镜头。

## 11. 运行时数据流

### 11.1 部署

```text
选择恐龙
  -> 显示五区边界
  -> 世界悬停点
  -> 共享部署服务检查区域/地面/NavMesh/间距/资源/UI
  -> 返回明确 DeploymentResult
  -> 合法时原子扣费并生成
  -> 清除或保持部署状态（由既有连续部署交互决定）
```

Human 和 AI 必须调用同一部署合法性服务。AI 可直接提供世界坐标或归一化动作，但最终仍映射到这五个区域和相同判定。

### 11.2 地表速度

```text
单位进入/离开地表判定区
  -> 解析当前最高优先级地表
  -> 基础速度 × 地表系数
  -> 导航继续使用统一 NavMesh
```

地表状态应是可观测、可测试的单一当前值，不能由多个组件分别累乘。

### 11.3 攻击

```text
目标进入攻击范围
  -> 目标选择与冷却检查
  -> 播放攻击表现并应用既有伤害效果
```

流程中不插入环境遮挡查询。

## 12. 异常与退化处理

- 部署点不在任一开放区、无地面、无 NavMesh、重叠、资源不足或被 UI 拦截时，拒绝生成和扣费，并返回唯一明确原因。
- 地表判定缺失时回退为草地 1.00×，同时在开发构建记录一次可定位警告，不让单位速度变为 0 或 NaN。
- 防御预设引用无效槽位时跳过该对象并报告错误；同 seed 的其余有效对象仍保持确定性。
- 精选 Kenney 资源缺失时使用现有 Dino Attack 占位物，不因装饰资源阻断玩法验证。
- 镜头配置异常时 Home 回退到预先验证的完整岛屿 Bounds。
- NavMesh 不可达时禁止把相关区域标记为验收通过；不能用传送或隐藏 waypoint 掩盖断路。

## 13. 验证策略

### 13.1 EditMode

- 五个区域的点包含、边界和相互独立性测试；北侧及已删除雨林空地必须不可部署。
- 所有恐龙类型在所有区域采用同一合法性规则。
- 五种地表系数、重叠优先级、进入/离开恢复、有限数值测试。
- 防御预设固定 seed 复现与无效槽位处理测试。
- 攻击回归测试：攻击者与合法目标之间放置房屋/岩石碰撞体后，攻击仍按既有距离和冷却生效。

### 13.2 PlayMode / 场景

- 每种恐龙分别从 Z1–Z5 生成并验证可到达中央广场，无卡角、脱离 NavMesh 或隐藏强制路线。
- 在石路、草地、泥地、坡地和浅水上测量实际移动时间，误差预算在计划中明确。
- 验证静态建筑和自然物会引起移动绕行，但不会阻断任何阵营的攻击。
- 验证同 seed 防御布局一致、不同预设均保持五区到广场可达。
- Setup、Running、Ending 的部署边界显示和清理行为正确。

### 13.3 视觉、镜头与性能

- 在 16:9、16:10、21:9 和 1280×720 检查开局/Home 完整岛屿构图。
- 检查中央广场、Z1–Z5、单位轮廓和非法原因不被 UI、树冠或山体遮挡。
- 对比改造前后的 CPU、GPU、内存、三角形、批次和 NavMesh 更新成本；先建立当前可比基线，再设定数值预算。
- Unity Console 不得新增 Error、异常、NaN、重复对象、永久速度修改或 NavMesh 脱网警告。

## 14. 验收标准

设计实现只有同时满足以下条件才可声明完成：

1. 玩家在默认完整岛屿镜头中能辨认村落、中央广场和五个部署方向。
2. Z1–Z5 始终开放，三种恐龙均可在每区合法部署并自主到达广场。
3. 地表速度实测符合 1.10/1.00/0.85/0.80/0.70 的统一倍率设计。
4. 没有固定三路、隐藏 waypoint 走廊、锁区、固定槽位或区域兵种限制。
5. 环境物影响移动与空间，但不阻挡任何攻击；UI 不宣称存在掩体防御。
6. 村落四区和中央广场均为可进入战斗空间，巨型山体不再主导画面。
7. 分散防御可破坏对象与静态建筑边界清晰，固定 seed 布局可复现。
8. 开局/Home 显示完整岛屿，RTS 平移缩放覆盖全部战区且不暴露大面积空白。
9. 新增美术保持暖色峡谷热带风格，Kenney 资源有 CC0 manifest 且仅精选导入。
10. 玩家模式、AI 模式、状态机、资源记账和胜负语义不因地图改造产生回归。
