# Dino Attack 恐龙战斗行为重构设计

**日期：** 2026-08-30

**状态：** 四部分设计已获用户批准，等待正式文档复核

**目标项目：** `dino-attack`

**目标场景：** `dino-attack/Assets/LlamAcademy/Dinos/Scenes/Dinos.unity`

## 1. 背景与问题定义

当前恐龙通过 Unity Behavior Graph 编排感知、选敌、移动和攻击。多只恐龙攻击同一目标后，部分恐龙会在目标死亡时永久停止。现有证据表明该现象不是因为多个恐龙共享同一个 Blackboard：`BehaviorGraphAgent` 会为每只恐龙实例化独立图和默认事件通道。

实际风险来自多个能够叠加的状态不一致：

- `AttackRadius` 和 `Dino` 使用可重复添加的原始目标列表，目标离开或死亡时只移除一个匹配项，并且列表在使用前没有形成可靠的“仅含存活目标”不变量。
- Behavior Graph 使用原始 `NearbyAttackables.Count > 0` 进入战斗分支；如果列表非空但只剩死亡、禁用或不可选择对象，选敌失败后不会保证恢复村庄路径。
- 攻击分支会停止并重置 NavMesh 路径，但失败路径没有统一恢复导航，因而可能形成“没有有效目标、也没有路径”的永久静止状态。
- 守卫死亡流程不是幂等的，受到同帧多次伤害或延迟伤害时，死亡事件和销毁流程存在重复触发风险。
- 即时伤害与延迟伤害的结束路径不同；非最后一击的恐龙不能稳定依赖“击杀事件”恢复自己的行为。
- 当前 Editor 日志还出现过 `BehaviorGraphModule.EndBranch` 内部空引用。它与分支结束时的停滞高度相关，但现阶段没有足够证据断言 Unity Behavior 1.0.13 是唯一根因。

本设计重构行为状态的所有权，使目标死亡、并发攻击、重新选敌和导航恢复具备明确且可测试的规则，同时继续使用 Behavior Graph 作为高层可视化编排工具。

## 2. 目标与非目标

### 2.1 目标

- 多只恐龙可以同时攻击同一目标，目标死亡后每只恐龙独立重新决策。
- 目标集合始终去重，并在读取前排除 null、死亡、禁用、不可攻击和不受支持的对象。
- 即时伤害、延迟伤害和协助攻击使用一致的目标失效与恢复语义。
- 任意目标的死亡事件、死亡表现、奖励和销毁逻辑至多执行一次。
- 恐龙没有有效攻击目标时始终恢复向村庄推进，不进入永久静止状态。
- 只有确认目标仍存活、可达且进入攻击范围后，才允许暂停 NavMeshAgent。
- 保留现有三种恐龙的目标优先级、攻击参数、动画、粒子、地貌速度和防御规则。
- 通过 EditMode/PlayMode 自动测试与真实战斗 smoke 覆盖多人共享目标场景。

### 2.2 非目标

- 不把恐龙行为改成纯 C# FSM、ML-Agents 个体控制器或新的训练动作空间。
- 不改变五个部署区域、地图空间结构、房屋布局或六选三防御布局。
- 不改变目标类别优先级、攻击数值、奖励数值、中央目标胜负语义或回合流程。
- 不恢复掩体、山体或废墟阻挡攻击的规则。
- 不把地貌速度纳入目标评分。
- 不擅自升级或降级 Unity Behavior 包。
- 不把关闭 Domain Reload 或 Scene Reload 固化为项目行为；验证使用干净加载会话，但项目设置变更需要独立批准。

## 3. 核心架构

### 3.1 职责边界

系统采用“Behavior Graph 编排、C# 保证状态正确性”的结构：

| 层 | 职责 | 不再负责 |
|---|---|---|
| `DinoTargetTracker` | 目标去重、订阅、存活验证、清理、当前目标失效通知 | 目标类别优先级和路径评分 |
| `DinoTargetSelector` | 按现有物种优先级和 NavMesh 可达性选择一个有效目标 | 保存目标生命周期 |
| `DinoCombatCoordinator` | 暴露 `HasLiveTarget`、管理当前战斗意图、保证无目标时恢复村庄导航 | 攻击动画和伤害数值 |
| Behavior Graph | 编排评估、接近、攻击、冷却和重新评估 | 直接信任原始列表数量、并行维护死亡事件 |
| 攻击 Action | 执行动画、计时和一次合法伤害提交 | 决定目标死亡后其他恐龙如何行动 |
| `Unit`/具体目标 | 幂等生命与死亡状态 | 通知某一特定恐龙“你击杀了目标” |

`DinoTargetTracker` 和 `DinoCombatCoordinator` 可以实现为两个小组件，也可以在实施时合并为一个职责清晰的组件；无论物理文件如何组织，上表中的所有权边界必须保持。

### 3.2 单一事实来源

每只恐龙拥有自己的目标追踪器。追踪器内部使用去重集合保存对象身份，并维护与 `IDamageable.OnDeath` 的一对一订阅关系。Behavior Graph 不再以可任意污染的 `List<GameObject>.Count` 作为战斗状态事实来源，而只读取：

- `HasLiveTarget`：当前是否存在至少一个经过验证的有效候选；
- `CurrentTarget`：当前选中的、仍有效的目标；
- `NavigationIntent`：`AdvanceToVillage`、`ApproachTarget` 或 `HoldForAttack`。

如果为兼容现有 Blackboard 必须继续写入 `NearbyAttackables`，它只能是追踪器生成的只读快照或经过完整清理的副本，不能再作为权威存储。

## 4. 目标生命周期

### 4.1 进入感知范围

```text
OnTriggerEnter
  → 查找 IDamageable
  → 验证对象启用、可攻击、Health > 0 且类别受支持
  → 按对象身份去重
  → 订阅一次 OnDeath
  → 加入该恐龙的候选集合
  → 请求下一次行为评估
```

重复的 Collider、重复进入事件或同一对象的多个 Collider 不得形成重复候选或重复死亡订阅。

### 4.2 离开、死亡或禁用

以下任一事件都通过同一个幂等移除入口处理：

- Trigger Exit；
- `IDamageable.OnDeath`；
- GameObject/组件被禁用；
- 对象被销毁或引用变为 null；
- 使用前验证发现 `Health <= 0`；
- 目标元数据失效或不再允许攻击。

移除入口执行：取消订阅、从集合删除、在必要时清空 `CurrentTarget`，然后请求重新评估。重复移除是安全的，不会再次发送退出事件。

### 4.3 清理时机

追踪器至少在以下时机执行清理：

- 选择目标之前；
- 读取 `HasLiveTarget` 之前；
- 攻击提交伤害之前；
- 目标死亡/退出/禁用事件到达时；
- 恐龙自身禁用或销毁时。

这保证临时事件丢失也不会长期保留无效目标。

## 5. 行为状态流

统一状态流为：

```text
Evaluate
  ├─ 存在有效目标
  │   → Select
  │   → Approach
  │   → ValidateInRange
  │   → HoldForAttack
  │   → Attack
  │   → Cooldown
  │   → Evaluate
  └─ 不存在有效目标
      → AdvanceToVillage
      → 周期性 Evaluate
```

### 5.1 评估与选敌

- 选择器只接收追踪器提供的有效候选快照。
- 保留三种恐龙现有严格目标类别优先级和同类 NavMesh 路径选择规则。
- 当前类别没有可达目标时才降级到下一类别。
- 所有候选均不可达或无效时，选择结果为“无战斗目标”，并立即切换到 `AdvanceToVillage`。
- 选择失败不是停住的理由，也不能留下上一目标的攻击意图。

### 5.2 接近与停止导航

- 选择目标后先计算并提交有效 NavMesh 路径，再进入接近状态。
- 接近期间每次更新验证目标；目标失效立即返回 `Evaluate`。
- 只有目标存活、可达且已经进入攻击距离时才能设置 `HoldForAttack`，并暂停或重置当前路径。
- 任一攻击前置条件失败时恢复导航意图，不能先清路径再验证目标。

### 5.3 攻击与冷却

- 攻击 Action 在启动、伤害生效和结束三个时点验证目标。
- 延迟攻击捕获的是一次攻击意图，不保证伤害必然提交；延迟结束时目标已死亡或失效则安全 no-op。
- 伤害提交只调用目标统一的幂等 `TakeDamage`，不得由 Action 重复派发另一套死亡语义。
- 攻击结束后无论命中、击杀、助攻、目标先被他人击杀或 Action 被中断，都返回 `Evaluate`。
- 现有物种攻击间隔、动画事件时刻和视觉效果保持不变；只统一状态结果。

## 6. 多只恐龙攻击同一目标

目标允许被任意数量恐龙选择，不引入目标锁、攻击席位或强制分摊。

当目标生命归零时：

1. 目标对象以幂等方式记录已死亡，只广播一次死亡事件。
2. 所有订阅该目标的恐龙追踪器各自移除目标并清除自己的 `CurrentTarget`（若匹配）。
3. 每只恐龙独立进入 `Evaluate`，不依赖谁造成最后一击。
4. 仍有有效目标的恐龙按自身物种优先级重新选择。
5. 没有有效目标的恐龙恢复村庄路径。
6. 已经排队但尚未生效的延迟伤害在提交时发现目标死亡，直接 no-op。

因此“击杀者”“非击杀者”和“延迟攻击者”共享同一个恢复规则。

## 7. Behavior Graph 重构

现有图简化为一个串行的重新评估循环，不再建立独立并行死亡监听分支：

```text
Alive Loop
  → Refresh Target State
  → Branch on HasLiveTarget
      ├─ Combat Sequence
      │   → Select/Validate CurrentTarget
      │   → Move To Target
      │   → Validate Attack Range
      │   → Stop For Attack
      │   → Attack
      │   → Cooldown
      └─ Advance Sequence
          → Ensure Village Destination
  → Repeat
```

设计约束：

- 分支条件读取 `HasLiveTarget`，不读取原始列表数量。
- 目标死亡只改变追踪器状态并请求重新评估，不由并行事件分支强制结束另一分支。
- Action 的 `OnEnd`、`OnDisable` 和失败路径必须幂等清理临时攻击状态。
- Action 不能在目标失效时保留 `HoldForAttack`。
- 图发生 Action 失败时必须落回重新评估，不允许失败后没有后续导航意图。

简化图能降低当前 `EndBranch` 异常的触发面，但不能仅凭设计宣称已经修复包内部异常。若干净会话中仍可复现相同堆栈，应把包兼容问题作为独立缺陷调查，不通过静默升级、降级或吞异常掩盖。

## 8. 导航恢复保护

`DinoCombatCoordinator` 维持一个明确的导航意图不变量：

```text
恐龙存活 && CurrentTarget 无效
  ⇒ NavigationIntent == AdvanceToVillage
```

当追踪器移除当前目标、选择器返回无目标、攻击 Action 中断或图重新评估时，协调器调用既有村庄目的地服务恢复路径。恢复操作必须幂等，避免每帧重复设置相同目的地。

保护逻辑不是另一套完整 FSM，也不主动替 Behavior Graph 选择攻击目标；它只防止“无有效目标且无导航意图”的非法状态。如果 NavMeshAgent 不在 NavMesh、已禁用或已经死亡，则不尝试设置目的地，并记录可诊断原因。

## 9. 死亡幂等与伤害契约

所有 `Unit` 类目标遵循：

- `Health <= 0` 或 `IsDead == true` 后，后续 `TakeDamage` 立即返回无状态变化。
- 第一次从存活变为死亡时原子化设置 `IsDead`，再广播一次死亡事件。
- 具体目标的死亡动画、Collider 禁用、奖励结算和延迟销毁只启动一次。
- 延迟销毁不得再次广播死亡事件。
- 房屋已经具备的一次性奖励语义保持不变，并纳入统一测试。

如果历史代码有消费者依赖“销毁时第二次死亡事件”，实施时必须迁移该消费者，不能保留重复广播。

## 10. 错误处理与诊断

- 追踪器发现缺失 `IDamageable`、不受支持的目标元数据或无效对象时，安全排除；开发构建可发出节流诊断，避免每帧刷屏。
- 选择器发现 invalid/partial/NaN/Infinity NavMesh 路径时把该候选视为不可达，继续尝试其他候选。
- 无任何可达候选时恢复村庄导航，而不是返回一个无后续动作的失败状态。
- NavMeshAgent 不在 NavMesh 时不调用 `SetDestination`/`ResetPath`，并保留明确诊断。
- 目标事件的订阅和取消订阅必须成对；恐龙或目标禁用后不得留下回调。
- 不通过 catch 并忽略 `BehaviorGraphModule.EndBranch` 异常完成修复；验证必须确认 Console 中不再出现相关异常。

## 11. 兼容性约束

保持不变：

- 迅猛龙、肿头龙、霸王龙的目标类别优先级。
- 同类别目标的 NavMesh 可达性和路径长度选择。
- 攻击力、攻击间隔、护甲、动画、粒子和音效配置。
- 地貌对恐龙速度和防御的现有影响。
- 山体、废墟和掩体不阻挡攻击结算。
- 村庄房屋、守卫、防御墙、中央目标和奖励规则。
- 玩家与 AI 共用同一恐龙生成和个体行为系统。
- 训练动作和观测协议。

本设计允许为新组件更新三种恐龙 Prefab 和 `Dino Graph.asset`，但不允许顺带改变场景布局、Packages 或无关 ProjectSettings。

## 12. 测试与验收

### 12.1 自动测试

测试先行，至少覆盖：

1. 同一对象多次进入只形成一个候选和一个死亡订阅。
2. 目标退出、死亡、禁用或销毁时幂等移除。
3. 原始集合含 null、死亡或禁用对象时，`HasLiveTarget` 为正确值。
4. 三只恐龙共享一个守卫；守卫死亡后每只恐龙都重新选敌或恢复村庄导航。
5. 非最后一击的恐龙不会停留在无路径状态。
6. 即时攻击和延迟攻击都不会对已死亡目标再次造成伤害。
7. 同帧多个致死伤害只触发一次死亡事件、死亡表现和奖励。
8. 一个目标死亡但另有有效目标时按原物种优先级切换。
9. 所有局部目标无效或不可达时恢复中央/村庄目标。
10. 目标尚未确认存活并进入攻击距离前不会重置路径。
11. Action 失败、中断和禁用后不会遗留 `HoldForAttack`。
12. 原有单只恐龙目标优先级、攻击节奏和移动测试继续通过。

### 12.2 Unity 集成验证

- 在没有第二个 Unity Editor 实例占用项目的情况下启动干净会话。
- 验证时启用完整 Domain Reload 和 Scene Reload，排除禁用重载造成的静态状态残留；除非用户另行批准，不永久修改项目设置。
- 完成脚本编译和相关 EditMode/PlayMode 测试。
- 在 `Dinos.unity` 中让至少三只恐龙共同攻击守卫、墙和房屋，连续完成多个目标切换。
- 检查恐龙在目标死亡后的当前位置、`CurrentTarget`、导航意图、`hasPath` 和下一次攻击。
- Unity Console 不得出现本流程引入的编译错误、空引用、重复死亡异常或 `BehaviorGraphModule.EndBranch` 异常。
- 如果包内部异常仍出现，保存完整堆栈和最小复现，再决定是否提出独立包版本变更方案。

### 12.3 完成标准

- 多只恐龙攻击同一目标后不会永久停止。
- 无论谁造成最后一击，所有存活攻击者都能在物种既有冷却时间加合理帧缓冲内继续行动。
- 无有效局部目标时恐龙始终恢复向村庄推进。
- 死亡、奖励和销毁逻辑至多执行一次。
- 原有玩法与训练协议没有非预期变化。
- 自动测试、Unity 编译和真实场景 smoke 均有可追溯证据。

## 13. 实施与回滚边界

实施采用测试先行的小步顺序：先建立多人共享目标与死亡幂等失败测试，再引入追踪器，随后统一伤害和导航恢复，最后简化 Behavior Graph。每一步都应能单独验证，并避免同时编辑无关 Prefab、场景或包配置。

工作区当前包含大量用户修改。实施时只修改本设计列出的相关脚本、测试、三种恐龙 Prefab 和 Behavior Graph；任何重叠文件必须先比较现有差异并保留用户工作。回滚以本任务新增文件和逐文件补丁为单位，不使用 `git reset --hard`、`git checkout --` 或 `git clean`。

本规格通过用户复核后进入详细实施计划编写；在计划再次确认前，不修改 Unity 代码、Prefab、场景、Packages 或 ProjectSettings。
