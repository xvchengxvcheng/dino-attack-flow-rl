# 基于简历的双岗位面试准备手册

适用方向：Unity 客户端／游戏 AI；强化学习／算法工程师。整理日期：2026-09-12。

依据：用户提供的《resume-zh_CN.pdf》完整一页，以及本项目 `docs/PROJECT_PLAN.md` 的历史证据与当前边界。简历 PDF 已渲染后逐项阅读，未修改原文件。技术原理另核对文末所列官方文档和原始论文。

本手册是学习材料和回答草稿，不是对个人贡献的认证。第一人称示例只有在与你的实际经历一致时才能使用；`【待补】`必须换成真实信息。无人机项目未提供源码、论文全文和实验表，因此相关回答解释原理、提供结构，不虚构实现细节、创新结论或性能提升。Dino 的数值属于计划中已有历史记录，本次没有重新运行实验。

## 1. 先确定你要让面试官记住什么

你的主线可以是：**数学与强化学习背景，能够把决策算法接入可运行的 Unity 游戏，并通过实验和测试检查它是否真的正确。**

这比逐个念出 Behavior Graph、PPO、MPC、Flow 等名词更有说服力。准备两种讲法，但个人经历、项目归属和数据口径必须一致。

| 方向 | 开场重点 | 重点项目 | 必须补齐的基础 | 适合展示的证据 |
|---|---|---|---|---|
| Unity 客户端 | 战斗逻辑、生命周期、调试与测试 | Dino Attack | C#、Unity 更新循环、内存、资源、图形学、数据结构 | 一条完整攻击链、一次可复现 bug、对应回归测试、游戏演示 |
| 游戏 AI | 行为编排与学习策略如何协作 | Dino + 强化学习部署 | 行为树、导航、状态／动作、推理成本、可控性 | 从观测到部署的全链路，非法动作与模型失效处理 |
| 强化学习算法 | 建模、目标函数、数据正确性与对照实验 | MAPPO–MPC + Dino Flow RL | 概率、优化、PPO／GAE、MARL、PyTorch | 手推公式、实验设计、失败分析、算法与工程贡献划分 |

建议复习分配：共同基础和项目证据 40%，Unity 专项 30%，算法专项 30%。某场面试确定方向后，再把最后两天偏向该方向。这是复习安排建议，不代表招聘市场统计。

## 2. 回答问题的通用方法

技术题按“**结论 → 原理 → 项目例子 → 验证／限制**”讲。项目题按“**背景 → 你的责任 → 具体行动 → 结果 → 复盘**”讲。

先给 30～60 秒核心答案，对方感兴趣再展开；每个项目另练 2 分钟和 5 分钟版本。每说一个指标，要能接着回答：哪个版本、多少样本、什么基线、训练还是冻结评估、哪个随机种子。

不知道时可以说：“这部分我没有实际实现过。我理解它主要解决【问题】，会先从【机制】分析，再用【实验／文档】确认。和我做过的【模块】相似的地方是【关联】。”不要只说不会，也不要把推测当成做过。

其中比较有代表性的问题，是同一个模型在不同 Python 回包延迟下会产生不同战斗结果。我通过对照实验定位时序影响，并参与固定步时钟改造和回归验证。希望应聘 Unity 客户端或游戏 AI 岗，把系统开发、调试和算法背景结合起来。”

### Q03. 两分钟介绍 Dino Attack

**回答草稿：**

“项目基于开源 Dino Attack 扩展反向塔防，简历所述版本支持三张地图以及玩家进攻、自由布防和 AI 对战。我把系统分成三部分讲。

第一是游戏规则：玩家和 AI 都通过 TryDeploy 提交部署，战斗对象通过行为图、黑板和 NavMesh 完成索敌、移动、攻击及死亡处理。

### Q04. 开源项目，你到底做了什么？

**回答方式：** “原项目提供【真实基础】；我负责【具体模块】；复用【已有实现】；修改【具体行为】。例如【触发条件】以前会【错误】，我通过【改动】使它【结果】，证据是【代码／测试／演示】。”

准备一张三列表：上游直接使用／自己修改与新增／工具辅助并由自己审查。不要回答“整个项目都是我做的”，也不要含糊地说“做了一些优化”。

**追问：** 去掉你做的部分会失去什么？为什么这样设计？有没有更简单方案？

### Q05. 你用了 Codex／Cursor，是不是主要由 AI 写的？

**回答草稿：** “我确实使用 AI 辅助开发，具体帮助包括【按实际填：代码草稿、检索、测试、文档】。我负责的部分是【按实际填：需求、接口、关键设计、审查、验证】。我的验收依据是代码行为和运行证据。例如【挑一个你能自己解释的 bug】，我能够独立说明复现条件、根因、修改和测试。对于不能独立解释的代码，我会先补齐理解。”

准备现场解释一个真实函数。工具使用本身不能证明工程能力；能否发现错误、验证结果、说明边界才是回答重点。

### Q06. 最有挑战／失败的一件事是什么？

**推荐故事：** 冻结模型在不同回包延迟下表现不同。讲清最初假设、如何固定变量、哪个结果否定旧解释、如何缩小范围、目前还差什么验证。

**第二故事：** FPO 短期探针没有崩塌，但长期训练再次退化。“这说明短期数值有限不等于长期策略稳定。我后来更重视行为指标、版本对应关系和更长验证窗口。”不要把尚未做的修复说成最终成功。

**追问：** 当时判断错在哪里？怎样更早发现？你下次会保留哪条检查？

### Q07. 为什么从数学转游戏开发／为什么同时考虑算法岗？

**回答草稿：** “数学训练让我习惯明确假设、建立模型和验证结论。在研究决策算法时，我发现自己也喜欢把系统真正运行起来，所以做了 Unity 战斗与 AI 项目。面对这份岗位，我更希望负责【结合 JD 填具体工作】，数学与算法背景可以帮助我处理空间计算、决策和实验问题。”

每场面试说明对该岗位的具体兴趣。不要把它讲成“算法岗找不到才试客户端”，也不需要虚构从小热爱游戏的故事。

### Q08. 弱点、团队分歧、未来规划怎么答？

**弱点：** 选真实、可改善的短板，例如“目前主要是研究和个人工程项目，缺少大型商业项目协作／移动端性能经验”，再说正在进行的具体练习。没有完成的行动不要说已完成。

**团队分歧：** 用真实案例说明目标和约束不同，你如何拿出小实验、比较方案、达成决定。不编造实习或带队经历；个人项目可以坦诚说明，然后讲设计取舍。

**规划：** 先能独立交付一个模块，逐步负责性能、稳定性或算法效果；不要只给职位名称。

## 4. Unity 客户端与战斗系统：Q09–Q28

### Q09. 玩家和 AI 为什么共用 TryDeploy？

**要学：** 命令入口、校验与提交、职责边界、结果码。

**回答：** “玩家点击和模型推理只是不同的决策来源。规则统一检查资源、位置、重叠、数量上限与回合状态，成功后才提交扣费和生成，失败则返回明确原因。这样训练和实际游戏不会分别维护两套规则。预览可以提前做检查，但最终执行仍要复核。”

**追问：** 生成失败是否退款？重复请求如何处理？同一帧状态变化怎么办？回答你现有实现，额外的请求 ID／事务设计应标为扩展方案。

### Q10. 重复伤害怎么防？

**要学：** 一次攻击实例、幂等、延迟回调、目标生命周期。

**回答：** “先区分两次合法攻击与同一次攻击重复提交。一次攻击应有明确开始、命中和结束；提交伤害前检查这次命中是否已经消费、目标是否仍有效。延迟命中不能仅依赖发起攻击时的引用。”

**追问：** A 目标死了，攻击者改打 B，旧回调还能命中 B 吗？范围攻击怎么既命中多个目标，又不对同一目标重复扣血？建议用攻击实例与目标绑定解释，不用一个全局布尔值草率解决。

### Q11. 目标死亡后，索敌和攻击怎样保持一致？

**回答：** “目标死亡后，移除候选集合并清理当前目标，取消或失效化相关延迟命中。行为图下一次执行时应重新选择目标或返回导航。读取黑板目标和真正提交伤害时都要验证存活状态，因为两者之间世界可能已改变。”

**追问：** 只有死亡事件够不够？对象被禁用、销毁、回收或场景卸载怎么办？对事件通知和使用前校验同时准备解释。

### Q12. 死亡与结算为什么需要幂等？

**回答：** “同一帧可能有多次伤害或多个终局触发源。如果每次都执行死亡奖励、资源返还或结算，会重复记账。应让 Alive→Dead、Running→Ending 等状态转换只成功一次，后续相同请求没有额外副作用。”

**追问：** 先置死亡状态还是先发事件？事件回调再次伤害会不会重入？死亡特效可以重复播放吗？

### Q13. FSM、行为树和学习策略怎么分工？

**回答：** “FSM 适合明确阶段与状态迁移；行为树适合条件判断、优先级和可组合任务；RL 策略适合从奖励学习决策。我的项目中部署策略决定在哪里、何时、部署什么，单位的移动和攻击仍由游戏行为系统执行。”

**追问：** 行为树的 Sequence／Selector 与 Success／Failure／Running 如何传播？任务 Running 时被打断，如何清理导航和回调？别把行为图中的每只恐龙都说成独立训练的 RL Agent。

### Q14. 黑板里应该存什么？

**回答：** “存行为节点需要共享的运行上下文，如当前目标、移动目标点和攻击状态。按单位隔离可变状态，避免不同单位互相覆盖。黑板引用不是对象持续有效的保证，节点执行时仍要做生命周期检查。”

**追问：** 哪些配置可共享？哪些状态必须是实例私有？ScriptableObject 适合存静态配置，但共享资源上的可变战斗状态容易串局。

### Q15. NavMeshAgent 不动，怎么查？

**回答：** “按链路检查：Agent 是否启用且在 NavMesh 上，目标是否可采样，路径是否完成计算，状态是 Complete／Partial／Invalid，是否被停止，速度和移动权限是否正常，最后看是否被其他脚本、动画或刚体反复改位置。”

**追问：** `remainingDistance` 小就一定到了吗？不是，还需考虑 `pathPending`、有效路径与业务目标距离。目标持续移动是否每帧重算路径？路径频率需结合目标变化和测量成本设计。

### Q16. Python 回包等待为什么会改变战斗结果？

**回答草稿：** “我先冻结模型和随机配置，只改变 Python 回传动作前的等待，确认结果变化来自时序干预。Unity 在等待期间主线程停止推进，但恢复后的帧调度会影响依赖 Update、FixedUpdate、行为图、协程和导航的逻辑。旧实现把不同时间基准混在一起，相同策略决策间可能发生不同数量或顺序的战斗事件。

改造把回合计时、攻击冷却、延迟命中和行为图的权威逻辑接入固定步时钟，再做延迟对照。它减少了偏差，但导航等子系统仍需单独验证，不能因此声称逐帧完全确定。”

**可选历史证据：** 主计划记录：旧版同一初始策略的合并对照为零等待 1/40、75 ms 等待 30/40；后续确定性对照达到 19/20 业务终局一致，仍有首局分叉。两组记录属于不同修复阶段与评估设置，不能拼成一个严格同条件性能提升数字。

**追问：** 固定了哪些变量？首次分叉如何找？建议比较 fixed tick、观测、动作、目标、攻击事件与位置，先定位首个不同点。

### Q17. Update、FixedUpdate、LateUpdate 分别干什么？

**回答：** “Update 随渲染帧执行；FixedUpdate 按固定游戏时间步推进，一个渲染帧内可以没有或有多次；LateUpdate 在 Update 后，常用于依赖本帧移动结果的相机跟随。固定步长并不意味着线程严格每隔固定墙钟时间运行，也不自动保证所有引擎子系统确定性。”

按所在回调和数值的物理单位选择时间增量。`velocity` 本身是速度，不能像位移那样再随意乘一次 `deltaTime`。原理参见 [Unity 执行顺序](https://docs.unity3d.com/6000.0/Documentation/Manual/execution-order.html)。

**追问：** 为什么输入边沿可能在 FixedUpdate 丢失？暂停时 UI 是否继续？这套固定步是否等于多人网络帧同步？后者还需要输入同步、确定性、校验与网络处理，不能混称。

### Q18. Awake、OnEnable、Start 怎么选？

**回答：** “Awake 做对象自身必要初始化；OnEnable 做与启用周期关联的注册；Start 适合首次运行前、依赖其他初始化已完成的准备。跨对象顺序不能仅凭函数名称或层级顺序猜测。停用和销毁要对应取消订阅、清理引用。”

用简历项目解释：如果存活判断在 Start 之前发生，而生命值只在 Start 初始化，就可能把新单位当死对象。改到更合适的初始化阶段后，仍应测试实际出生入口。

**追问：** 对象池再次激活会不会再次调用 Start？通常不会把它当作每次取出都执行的重置入口，复用状态要显式重置。

### Q19. 协程、async／await、线程是什么关系？

**回答：** “Unity 常用协程把过程分段，由主循环继续执行，通常仍在主线程，不能让重计算自动并行。async／await 描述异步等待，不等于自动新建线程；是否并行取决于具体操作和调度。后台任务完成后，访问大部分 Unity 对象需要回到主线程，并考虑场景退出和取消。”

**追问：** `WaitForSeconds` 是否精确计时？会受缩放时间和帧恢复点影响。任务完成时对象已销毁怎么办？异步异常在哪里观察？原理参见 [Microsoft 对 async／await 的解释](https://devblogs.microsoft.com/dotnet/how-async-await-really-works/)。

### Q20. C# class、struct、装箱怎么答？

**回答：** “class 变量持有引用，赋值通常复制引用；struct 具有值语义，赋值通常复制其值。不能把区别简单背成 class 在堆、struct 在栈，实际存储取决于上下文。值类型转为 object 或某些接口使用会发生装箱，可能产生分配和复制；泛型常有助于避免不必要装箱。”

**追问：** struct 里有引用字段，复制后引用对象是否深拷贝？没有。大型 struct 频繁复制有什么成本？`ref`／`in` 的语义是什么？参见 [值类型](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/value-types)、[装箱与拆箱](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)。

### Q21. delegate、event、接口分别解决什么？

**回答：** “delegate 表达可调用方法；event 限制外部对订阅关系和触发的操作，适合通知；接口规定一组能力，适合将规则依赖与具体实现分开。伤害能力可以通过接口表达，死亡通知可以通过事件传播，具体形式按已有架构选。”

**追问：** 为什么事件会导致对象不能回收？发布者持有订阅者引用；生命周期不匹配且未退订会滞留。匿名 lambda 如何退订？保存同一委托实例。静态事件切场景尤其要检查。

### Q22. GC 卡顿与对象池怎么解释？

**回答：** “先用 Profiler 找到分配和回收相关的帧尖峰，再检查热路径的临时对象、字符串、闭包、装箱、集合扩容和频繁实例化。对象池复用高频对象，但必须重置生命、目标、事件、计时器、特效和旧任务；池也有占用内存和管理成本。”

**追问：** 对象池能解决所有 GC 吗？不能。怎样防止旧攻击回调命中被复用的新对象？可考虑代次令牌或取消机制，明确这是设计方案还是已实现能力。不要背“所有 foreach／LINQ 都一定分配”，要看调用方式和实际测量。

### Q23. 战斗帧率低，如何定位？

**回答：** “在目标平台的代表性战斗中复现，先区分 CPU、GPU、内存或同步等待，再看主线程、渲染、物理、导航、动画和脚本开销。找到热点后一次改一类问题，用相同场景和负载比较平均帧时间与尾部卡顿。”

**追问：** 1000 个单位每帧找最近敌人的复杂度？朴素全互查近 O(N²)，可考虑空间网格、降低感知频率或缓存，但要评估动态更新成本和玩法延迟。没有测量就不要说“优化后提升 50%”。

### Q24. UI Toolkit 按钮可见但点了没反应，怎么查？

**回答：** “先查遮挡、拾取、启用状态和事件传播，再核对回调是否绑定在当前显示的元素实例上。UIDocument 的可视树可能重建，旧引用上的回调并不会自动变成新树回调。应在合适的生命周期重新查询和绑定，并清理旧订阅。”

**追问：** 反复重试为什么点击一次执行多次？可能重复订阅。只直接调用 handler 能证明真实按钮正常吗？不能，还要覆盖实际输入和当前 live tree。

### Q25. EditMode 和 PlayMode 怎么分？

**回答：** “纯规则、配置与可独立执行的逻辑优先放快速测试；依赖生命周期、物理、实际场景与模型运行的用 PlayMode／运行验证。围绕错误行为写断言，例如资源不足不能扣费、死亡目标不能被旧攻击再次命中、结束事件只能提交一次。”

**追问：** 测试通过为什么玩家仍发现 bug？测试可能没有覆盖实际交互、完整生命周期、构建环境或视觉表现。说明测试覆盖范围，不把定向测试通过说成整个游戏全绿。

### Q26. 你写了熟悉 Game Framework，具体熟悉什么？

**回答前先澄清：** 你指的是某个具体开源 Game Framework，还是一般游戏框架设计。简历未给出版本和实战模块，必须本人补齐。

**回答结构：** “我实际使用／阅读过【框架、版本】中的【模块】，理解它通过【机制】解决【问题】。在本项目中使用的是【实际情况】。”若主要是学习，可以说了解事件、资源、对象池、流程／状态管理等模块职责，不说已完整搭建商业框架。

**追问：** 资源如何释放？模块依赖怎么管理？事件、流程与 UI 生命周期怎么关联？只答模块名称不够。

### Q27. 图形学与空间数学，至少会什么？

**回答要点：** 点积用于夹角／朝向投影，叉积用于垂直方向；位置与方向的变换不同；模型、世界、观察、裁剪空间的转换顺序；透视除法；法线变换在非均匀缩放下要考虑逆转置；四元数插值与旋转次序。

**项目练习：** 判定敌人是否在攻击扇形内；求屏幕射线与地面交点；解释四边形区域 `(u,v)` 到世界位置；画一次相机跟随和遮挡检测。

**追问：** 渲染批次、材质切换、透明排序、overdraw 分别是什么？讲原理即可，没有 Shader／移动端项目就不虚构成果。

### Q28. 手写客户端代码会考什么？

优先练：哈希去重、队列、堆／优先队列、BFS／A*、二分、链表、对象池、事件订阅、简单状态机和空间查询。

**现场流程：** 先确认输入与边界，给简单正确方案，说明复杂度，再优化；边写边举例验证。你应能独立写“攻击只结算一次”“从候选集合删除无效目标”“最近 K 个敌人”中的两个。

**追问：** 空集合、对象失效、重复 ID、等距、取消、重复释放怎样处理？C# 代码要解释 Dictionary／HashSet 的键相等与哈希行为。

## 5. 强化学习、Flow 与部署：Q29–Q48

### Q29. Dino 的 MDP 怎么定义？270 维是什么？

**回答：** “策略是部署决策者。观测包含全局信息、区域几何、墙、守卫、房屋和恐龙；动作表达区域、区域内坐标和等待／兵种选择；环境负责战斗演化和奖励。观察未必包含完整世界状态，所以还要检查马尔可夫性，不能仅把它叫 state 就认为充分可观测。”

| 观测流 | 固定容量 shape | 标量数 |
|---|---|---:|
| Global | (5,) | 5 |
| Regions | (5,8) | 40 |
| Walls | (6,5) | 30 |
| Guards | (11,7) | 77 |
| Houses | (8,6) | 48 |
| Dinos | (10,7) | 70 |
| 合计 | 六路输入 | 270 |

**追问：** 为什么实体数量能变化，但输入 shape 固定？采用容量上限、有效标记和掩码；死亡／缺失槽不应作为真实实体参与聚合。270 标量不是 270 个实体。

### Q30. 4 维动作中有离散选项，为什么用连续策略？

**回答：** “现有合同用连续向量统一表达区域、坐标和兵种／等待，部分维度经分桶解码。优点是接入连续策略方便；代价是阈值附近的小变化可能切换类别，连续均值不一定对应合理的离散选择，而且需要处理非法组合。”

**追问：** 为什么不用混合策略头和 action mask？这是值得做的对照设计，但会改变概率模型、动作合同和基线，不能说项目已实现。掩码也应在采样与 log-prob 计算中保持一致。

### Q31. 为什么用 Set Transformer？

**回答：** “敌我实体具有集合结构，按固定列表位置展平容易引入无意义的顺序依赖。集合注意力可以建模实体间关系，再聚合为固定长度特征。没有位置编码等破坏条件时，自注意力的实体输出对重排等变，配合不变池化才能得到整体不变表示；不能说 Transformer 天然总是不变。”

**追问：** Deep Sets 更简单，为什么不用它？比较交互建模能力与成本。普通注意力约 O(N²)，固定 m 个诱导点的 ISAB 可降低到约 O(Nm)；还要测实际小集合下的开销。空集合和全 mask 怎么避免 NaN？参见 [Set Transformer 原论文](https://proceedings.mlr.press/v97/lee19d.html)。

### Q32. ML-Agents 为什么必须按 Agent ID 对齐？

**回答：** “某次 DecisionSteps 的第 i 行不保证下一次仍是同一 Agent。提交动作必须按当次决策顺序组织，接收后续奖励时按身份找之前的动作。并行和重启后，单独 Agent ID 还不够，应结合环境、进程代次和 episode 身份。”

**追问：** 空 DecisionSteps、只有 TerminalSteps、同一 Agent 重新出生怎么办？先定义 pending action 和终止清理，再验证 shape／dtype／边界。API 语义参见 [ML-Agents LLAPI](https://unity-technologies.github.io/ml-agents/Python-LLAPI/)。

### Q33. 异步并行采样与 GPU 动态批处理如何工作？

**回答：** “多个 Unity 进程各自推进，谁产生决策就进入待推理队列，汇总成 GPU 微批，再把动作按来源分发。这样减少所有环境等待最慢环境的浪费，但排队、拷贝和回包本身也有成本，环境数增加不保证吞吐增加。”

**追问：** 大 batch 一定更快吗？需要同时测吞吐和单个请求的等待／延迟。PPO 的 rollout 是一轮采样数据，minibatch 是优化时切分的小批，推理 microbatch 是第三个概念，不能混用。

### Q34. 异步采样为什么还能做 on-policy？

**回答：** “环境完成顺序可以异步，但策略更新需要版本边界。采样期间使用指定的行为策略版本，记录 old log-prob 或算法所需的行为快照；达到 rollout 边界后处理在途数据，再更新。来自不同版本的数据不能因为在同一队列里就直接合并。”

**追问：** 更新后才收到旧动作的结果怎么办？依赖该 transition 的行为版本与快照，按合同纳入对应批或明确丢弃；不能用新网络倒算旧概率。只有 old log-prob 并不能让任意陈旧 replay buffer 自动适合 PPO。

### Q35. terminal 和 truncated 对 GAE 有什么区别？

**回答：** “自然终止表示任务未来价值结束，自举为零；时间采样上限等人为截断，如果保留有效的最终观测，通常仍估计后续价值，但不能把优势递推接到 reset 后的新回合。进程崩溃若没有可信下一状态，不能伪造观测做自举，应按数据合同排除或单独处理。”

用两个 mask 区分：

`delta_t = reward_t + gamma * bootstrap_mask_t * V(next_obs_t) - V(obs_t)`

`adv_t = delta_t + gamma * lambda * continuation_mask_t * adv_(t+1)`

bootstrap mask 回答“有无可用未来价值”；continuation mask 回答“后面还是同一条连续轨迹吗”。项目 50 秒耗尽是任务规则中的自然失败，不因名称里有 timeout 就自动当截断。

**追问：** 接口自动 reset 后返回的新观测可否当最后状态？不可以。LLAPI 的 interrupted 需要按合同映射，且检查终止观测可用性。

### Q36. PPO 的目标函数是什么？为什么 clip？

令 `r_t(theta) = exp(log_pi_new - log_pi_old)`：

`L_clip = E[min(r_t * A_t, clip(r_t, 1-epsilon, 1+epsilon) * A_t)]`。

**回答：** “优势表示这个动作比状态平均水平好多少。比率衡量新策略相对行为策略对该动作的支持程度。裁剪限制代理目标继续奖励某些过大的有利变化，缓和多轮更新带来的策略偏移。它不是把所有概率比、参数变化或真实 KL 硬限制在阈值内。”

**追问：** A 为正、为负时分别哪侧被截断？loss 是最大化还是最小化？actor、critic、entropy 如何组合？`old_log_prob` 和 advantage 为什么通常 detach？参见 [PPO 原论文](https://arxiv.org/abs/1707.06347)。

### Q37. GAE 的 gamma 与 lambda 分别控制什么？

没有轨迹边界时：`A_t = sum_l (gamma * lambda)^l * delta_(t+l)`。

**回答：** “gamma 定义折扣目标，lambda 控制不同长度 TD 估计的混合。lambda 小通常更依赖 critic，方差较低但可能有更多估计偏差；接近 1 更依赖长段采样。这里的偏差与 critic 准确性及边界处理相关。”

**追问：** 开局等待是否就是 lambda 小？不能直接归因。还需检查奖励权衡、动作分桶、探索、数据和冻结行为，做单变量对照。手算一个含自然终止、一个含截断的三步例子。参见 [GAE 原论文](https://arxiv.org/abs/1506.02438)。

### Q38. 为什么 tanh 后 log-prob 要修正？

若 `u ~ Normal(mu, sigma)`，`a = tanh(u)`，则

`log p(a) = log p(u) - sum_j log(1 - tanh(u_j)^2)`。

**回答：** “变量变换改变密度，需要 Jacobian。实现时保留 pre-tanh 值，并用稳定写法避免饱和区间下溢。若额外映射到其他动作区间，还需考虑缩放。”

**追问：** 直接 clip Gaussian 会不会一样？不会，clip 是多对一并产生边界概率质量。tanh(mu) 是否等于动作分布均值？一般不等于 E[tanh(u)]。同一变换在某些概率比中可抵消，也不能据此把绝对 log-prob 或熵全部写错。

### Q39. 训练成功率很高，部署为何很差？

**回答：** “依次检查同一个 checkpoint、构建和配置；相同观测预处理与动作解码；随机采样和确定性输出差异；决策频率和时序；地图与种子；最后区分训练日志的行为版本和冻结评估。只比较两条曲线不足以判断根因。”

**追问：** batch1 和 batch16 是否一致？归一化是否在 eval 时更新？模型是否处于 eval 模式？平均动作会不会跨过兵种分桶？同样胜率不代表轨迹逐步相同。

### Q40. ONNX 导出后怎样验收？

**回答：** “先验证输入名称、shape、dtype、归一化、实体 mask、输出范围和算子支持；用固定输入在 PyTorch、ONNX 运行器和实际 Unity 推理端比对输出，再在游戏里验证动作执行与生命周期。保留 checkpoint、配置、导出模型和环境版本的对应关系。”

**追问：** checker 通过就能部署吗？不能证明运行器支持、数值一致或游戏策略正确。还要测目标设备的预热、延迟、内存和资源释放。项目沿用 Sentis 称呼，学习时核对实际包版本；官方见 [Unity AI Inference 文档](https://docs.unity3d.com/Packages/com.unity.ai.inference@2.6/manual/index.html)。

### Q41. Flow Matching 到底学什么？

**回答：** “它学习一个随时间变化的速度场，把简单噪声分布逐步变成数据／动作分布。以线性条件路径为例，采样噪声 z、示范动作 a 和 t，构造 x_t=(1-t)z+t*a，目标速度是 a-z，回归 v_theta(x_t,t,s)。推理时从噪声出发数值积分得到动作。”

**追问：** 流时间 t 和环境时间有什么区别？一个是生成一次动作内部的时间参数，另一个是游戏演化。监督的速度场不是无人机物理速度。具体数据坐标与输出变换必须一致。参见 [Flow Matching 原论文](https://arxiv.org/abs/2210.02747)。

### Q42. FPO 和 PPO 的关键区别是什么？

**回答：** “高斯 PPO 容易计算动作 log-prob；Flow 策略的精确密度计算更昂贵。FPO 用新旧策略在同一样本上的条件流匹配误差变化构造代理比率，再结合带符号优势和 PPO 风格裁剪更新。它让 Flow 策略能接受奖励优化，但这个比率不能直接叫精确动作概率比。”

**追问：** 为什么新旧计算要共享 t 和噪声？有助于减少差值估计的额外随机波动。负优势意味着什么？需要降低对应样本的支持，不能退化成只拟合好动作的 BC。loss 差值截断、MC 聚合与指数的先后顺序应对照固定实现，不能凭示意公式改写。参见 [FPO 原论文](https://arxiv.org/html/2507.21053v1)、[官方仓库](https://github.com/akanazawa/fpo)。

### Q43. PolicyFlow 和 FPO 有什么不同？

**回答：** “PolicyFlow 以 Flow 输出加高斯扰动构造策略，利用插值路径上的新旧速度场变化近似终点偏移，据此形成 PPO 风格的比率目标，并引入 Brownian 正则促进多样性。FPO 的核心则是条件流匹配误差差值。两者的概率建模、行为快照和正则项不能直接互换。”

**追问：** 推理是否不再需要积分？仍需要；简化的是更新目标中的计算。固定 z 的条件概率与对 z 积分后的边缘动作概率是不是一回事？不是。你的 PPO 数据预训练属于本项目初始化流程，不要把它说成算法定义本身。参见 [PolicyFlow 原论文](https://arxiv.org/html/2602.01156v1)、[官方实现](https://github.com/PolicyFlow2026/PolicyFlow)。

### Q44. Flow 比 Gaussian 好在哪里，代价是什么？

**回答：** “条件动作可能有多个有效方案，Flow 提供更灵活的分布表示。是否更好仍需任务实验；它的积分、更新估计与调参都有成本。应同时报告回报、多样性、环境步、墙钟时间、延迟、显存和实际网络调用次数。”

**追问：** NFE 是什么？生成动作时 velocity 网络实际调用次数。Euler 一步通常一次，中点法一步通常两次；NFE 4 不能直接理解为 4 个中点积分区间。零 latent 的输出是不是平均动作或最高概率动作？通常都不能保证。

### Q45. 为什么先收集 PPO 成功轨迹做 Flow BC？

**回答：** “用已有成功行为给生成策略较好的初始化，再尝试在线优化。但成功回合中的每一步不一定都是有效或优质动作。需要检查非法动作、等待比例、地图和兵种覆盖，按完整 episode 划分训练验证集，避免同回合相邻样本泄漏。”

**追问：** BC loss 降低是否等于游戏成功率上升？不是，要冻结运行。教师 bounded action 直接当 Flow 终点，输出再 tanh 是否等价？不等价，应检查动作空间定义；如采用 pre-tanh 训练，需处理边界并重新验证。此处是检查点，不表示历史实现已修复。

### Q46. FPO 训练突然崩塌怎么排查？

**回答：** “先确认是统计还是行为退化：按行为策略版本匹配 checkpoint，检查每地图成功率、超时和非法动作；再排查 worker 重启、数据错配、环境构建与时钟。若外部条件稳定，再检查 ratio、KL 代理指标、clip fraction、梯度和参数变化，提出受控消融。”

**追问：** 没有 NaN 为什么也会崩？数值有限不代表更新小或策略好。可以考虑降低学习率／epochs、收紧裁剪、增加采样或更新停止条件，但不同改动要分别验证。代理 KL 不冒充精确动作分布 KL。

### Q47. 怎样公平比较 PPO、FPO、PolicyFlow？

**回答：** “固定环境、观测动作和评估协议，报告训练 seeds、样本预算、调参预算、模型规模、动作模式和资源开销；冻结候选模型后用独立评估集比较。PolicyFlow 的教师数据与 BC 成本单列，热启动、精确恢复和从零训练分开记录。”

**追问：** 同环境步是否已公平？不足，还要看额外数据与计算。40 局是否能证明小幅优势？不够，应报告样本量与不确定性。项目目前尚未完成严格统一比较，不能从不同 seed／checkpoint 的历史百分比排算法名次。

### Q48. 为什么学会等待，而不是立刻部署？

**回答：** “先确认模型真的持续输出 Wait，还是部署被拒绝。等待可能与资源奖励、部署成本、终局惩罚、观测时间、探索和离散分桶有关。固定状态只改变时间可以发现敏感性，但不能直接证明真实环境中提前部署更优。”

**追问：** 怎么验证成因？记录原始动作和解码结果，在同布局下干预首部署时间，控制其他变量比较结果；再针对奖励或 lambda 做消融。训练原因、离线输入敏感性和实际因果收益要分开。

## 6. 多智能体、MPC 与无人机科研：Q49–Q60

这些题以简历为线索；回答中的具体维度、求解器、约束、基线与结果必须从你自己的论文或代码补齐。

### Q49. 什么是 Dec-POMDP？为什么你的任务这样建模？

**回答：** “多个智能体共同影响环境，各自只看到部分信息并做局部决策，任务目标具有协作性。要说明全局状态、每机观测、联合动作、状态转移、共享或个体奖励，以及执行时实际可用的信息。”

**追问：** 队友信息怎么获得？有通信延迟和丢包吗？如果 actor 使用仿真器全局真值，不能无条件声称部署是局部可观测。是否用 RNN 表示历史，按实际实现回答。

### Q50. CTDE 和 MAPPO 是什么？

**回答：** “集中训练、分散执行允许 critic 在训练时使用更充分信息来评价联合局面，actor 执行时只使用约定可获得的观测。MAPPO 把 PPO 更新用于协作多智能体，常结合集中式价值函数、参数共享和价值归一化。”

**追问：** actor 共享参数是不是必须？不是，取决于同质性。集中 critic 是否需要直接输入联合动作？MAPPO 常用状态价值，不能和 MADDPG 的 Q 输入混为一谈。参见 [MAPPO 原论文](https://arxiv.org/abs/2103.01955)。

### Q51. MAPPO 与 MADDPG 怎么比较？

| 维度 | MAPPO 常见形式 | MADDPG 常见形式 |
|---|---|---|
| 数据 | on-policy rollout | off-policy replay buffer |
| actor | 随机策略 | 确定性连续策略，训练加探索 |
| critic | 集中式状态价值 | 集中式 Q，利用联合信息与动作 |
| 更新 | PPO 裁剪目标 | 确定性策略梯度、目标网络 |

**回答补充：** “算法选择取决于数据成本、任务连续性、稳定性和实现。我的二维项目使用 MADDPG，后续 MAPPO 项目还改变了【实际场景与控制设计】，所以不能仅凭两组结果证明 MAPPO 优于 MADDPG。”

**追问：** 多智能体非平稳性来自哪里？其他 agent 也在学习。集中 critic 能缓解问题，但不保证消除全部非平稳性。参见 [MADDPG 原论文](https://arxiv.org/abs/1706.02275)。

### Q52. MPC 是什么？请写出优化问题

可从通用形式讲起：

`min sum_(k=0)^(H-1) [||x_k-x_ref_k||_Q^2 + ||u_k||_R^2] + V_f(x_H)`

约束：`x_(k+1)=f(x_k,u_k)`，`x_0=x_measured`，`x_k in X`，`u_k in U`，加上具体避障／可行域约束。

**回答：** “每次根据当前状态预测未来一段时间，求满足约束的控制序列，只执行第一段，再根据新观测重算。这形成反馈，能不断修正模型与扰动误差。”

**追问：** 线性模型与二次代价能构成 QP 的条件是什么？约束也应满足相应凸性条件。你的六自由度系统是否线性化、用哪种求解器、H 和 dt 多少？这些必须填真实值。原理参见 [Rawlings 等的 MPC 教材](https://sites.engineering.ucsb.edu/~jbraw/mpc/)。

### Q53. 为什么采用 RL–MPC 分层？接口是什么？

**回答草稿：** “高层策略处理协作和子目标选择，低层 MPC 把参考转成满足模型与约束的控制。相比端到端直接输出底层控制，分层让约束处理更明确，但会增加接口设计和优化计算成本，也受模型精度与可行性影响。”

**必须补：** 上层输出是位置、速度、航向还是其他参考？多久更新一次？低层控制频率是多少？不可行子目标如何处理？你是否把执行误差反馈给策略？

**追问：** RL 是否一定解决全局最优，MPC 是否一定安全？都不能无条件保证。如果高层一次动作覆盖多次低层控制，要说明奖励聚合和折扣对应的时间尺度。

### Q54. 障碍物怎么变成局部凸可行域？

**回答：** “用多个半空间约束 `a_i^T p <= b_i` 的交集表示局部多面体，便于接入优化器。关键是这些平面如何从障碍几何构造，哪一侧是安全区域，是否包含当前位置或参考轨迹，并保留无人机尺寸与误差的裕量。”

**追问：** 对障碍点求凸包就是安全空间吗？不是。点云稀疏时会不会漏障碍？相邻局部域有无重叠？可行域为空怎么办？不要把“局部凸”说成全局最优或全局安全证明。

### Q55. Fibonacci 射线采样解决什么，限制是什么？

**回答：** “在球面上较均匀地选取方向，沿射线感知或查询周围几何，为局部障碍表示提供样本。相较经纬度网格，它可以减少极区采样聚集，但有限方向仍可能漏掉细小障碍。”

**必须补：** 射线数量、半径、更新频率、聚合压缩方法及误差准则。压缩点云减少计算也可能损失几何细节，要说明保守处理。

**追问：** 为什么这一分辨率够用？用不同障碍尺度、密度和采样数做碰撞率／耗时对照，而不是只展示一张漂亮轨迹图。

### Q56. 六自由度、四元数分别指什么？

**回答：** “刚体六自由度是三维平移与三维旋转，不等于状态向量只有六维。动力学可能包含位置、速度、姿态、角速度等。四元数用四个受单位范数约束的分量表示旋转，可避免欧拉角某些奇异问题。”

**追问：** q 与 -q 表示同一旋转；乘法次序涉及坐标系；积分后如何保持归一化？控制输入是推力力矩还是电机转速？只有运动学模型时不能称已实现完整动力学。

### Q57. 追踪、围绕、收缩、保持四阶段奖励怎么设计？

**回答：** “先定义可测的行为目标，例如接近目标、改善空间包围、达到合适距离和维持结构，再确定连续奖励与阶段切换。要检查奖励尺度、切换抖动、与碰撞／控制代价的权衡，以及策略是否能刷分却不完成任务。”

**追问：** 阶段阈值是什么？共享奖励的信用分配怎么处理？个体都追最近点会不会聚成一团？消融应比较无分阶段、删除某项奖励、不同目标速度和队伍规模，报告实际结果。

### Q58. Lévy flight 和自适应差分进化为什么加入雪雁算法？

**回答结构：** “原方法在【你观察到的现象】下表现不足，因此引入【公式和触发条件】。Lévy flight 的重尾步长用于增加较大范围探索的机会；差分进化利用种群差向量产生搜索方向，自适应机制调整【真实参数】。我通过【真实消融】检验改动是否有效。”

**追问：** 不是所有问题都受益，怎样处理越界、约束和无效路径？保持相同函数评估次数比较，比只保持迭代轮数更合理。必须补原方法来源、公式、随机种子和计算预算，不虚构全局收敛保证。Lévy 搜索机制可参考 [Yang 与 Deb 的原始论文](https://arxiv.org/abs/1003.1594)；这只是背景资料，不是你所用雪雁算法或个人改进的来源认证。

### Q59. 三次样条平滑后就一定是可飞轨迹吗？

**回答：** “不是。样条能改善几何平滑，但可能偏离原折线并穿过障碍，也可能超出曲率、速度、加速度或动力学约束。要在平滑后重新验证连续路径的安全性，并明确时间参数化。”

**追问：** 只检查控制点不够；稀疏采样也可能漏碰。怎样设置采样误差界或用更强几何检查？几何路径、带时间轨迹、动力学可执行控制是三个层次。

### Q60. 你的创新是什么？论文结果怎么讲？

**回答模板：** “已有方法主要解决【问题】，在【具体条件】仍存在【缺口】。我的贡献是【本人实际提出／实现的内容】，核心机制是【解释】。实验在【场景、规模、预算】下与【基线】比较，用【指标】评价；【消融】支持了【范围内结论】。目前限制是【真实限制】。”

**追问：** 只是把两个算法接起来吗？回答接口、建模、约束或实验证据中的具体新内容，不用“融合后创新性很强”代替机制。发表状态与作者顺序准确说；SCI 在投不能说已录用。没有论文全文与实验表支持时，先整理证据再背数值。
