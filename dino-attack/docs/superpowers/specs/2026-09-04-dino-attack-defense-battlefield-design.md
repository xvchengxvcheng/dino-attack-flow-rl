# Dino Attack 地图三“防御战场”设计

**日期：** 2026-09-04  
**对应阶段：** 阶段 8 / `TASK-8.11-MAP3`  
**状态：** 对话设计已批准  
**实施工作树：** `dino-attack/.worktrees/ui-enhancement`（分支 `codex/ui-enhancement`）  
**事实来源：** 外层 `docs/PROJECT_PLAN.md`

## 1. 目标

新增独立正式场景 `DefenseBattlefield.unity`，玩家显示名为“防御战场”。地图三完整复用地图二“分层战场”的房屋生成、五个恐龙部署区、地貌、摄像机、战斗数值、结构化观测和嵌入式 AI 推理；唯一核心玩法差异是防御布局由玩家在开战前自由设置。

玩家必须放置3面城墙、5名地面弓箭手和3名法师。每面城墙自动附带1名墙上弓箭手。完成布防并明确选择一个可用的 PPO、FPO 或 ReinFlow 模型后，玩家在不重载场景的情况下启动 AI 进攻。

## 2. 非目标

- 不修改地图二的自动防御布局、玩家进攻流程或训练流程。
- 不为地图三训练、微调或伪造专用模型；地图三直接复用对应的地图二模型。
- 不改变 `dino_attack_structured_set_v2` 的六流270标量观测、4D动作或25模拟步决策周期。
- 不增加新的兵种、恐龙、资源、美术包、相机系统或战斗数值。
- 不把鼠标布防输入放入 `EnemyAIController`，也不由 UI 脚本直接实例化战斗对象。
- 不持久化玩家布防到磁盘；布局只在当前结算重试链中临时保存。

## 3. 场景与共享边界

### 3.1 独立场景

- 稳定地图 ID：`defense_battlefield`。
- Unity 场景：`Assets/LlamAcademy/Dinos/Scenes/DefenseBattlefield.unity`。
- 玩家显示名：`防御战场`。
- MapSelect 第三个地图按钮点击后直接加载地图三并进入布防阶段，不再显示玩家/AI控制模式选择。
- 场景以 `LayeredBattlefield.unity` 为模板，通过 Unity Editor builder 复制和接线；不得手改场景 YAML。

### 3.2 与地图二完全一致的内容

- 同一布局 seed 产生相同的房屋、房屋 Tier、房屋位置、目标位置、Z1–Z5 预设和地貌表现。
- 初始肉量 `50`；房屋首次摧毁奖励 `100` 肉；恐龙成本 `25/50/100`。
- 单局最长50秒模拟时间。
- AI 可在战斗期间持续决策、等待或部署恐龙，获得房屋及防御摧毁奖励后可继续增援。
- 摄像机完整复用地图二 `CameraControl`：边缘/键盘平移、鼠标中键拖动、滚轮缩放和世界边界限制。
- 守卫、墙、恐龙 Prefab、生命、攻击、移动、目标选择、VFX、音效、NavMeshData 和 UI 视觉语言均沿用现有资源。

### 3.3 唯一玩法差异

地图二由 `SessionDefenseLayoutController` 和 `SessionGroundDefenseController` 根据 seed 自动生成防线；地图三禁用这两个自动生成入口，改由 `DefensePlacementController` 接收玩家输入并生成同样数量、同样类型、同样战斗属性的防御对象。

## 4. 生命周期

地图三使用以下显式阶段：

1. `GeneratingLayout`：按地图二规则应用房屋、目标和五区布局。
2. `EditingDefense`：玩家自由布防；AI、恐龙部署和守卫战斗逻辑均未启动。
3. `StartingBattle`：锁定布局、隐藏预览与部署区、验证模型并原地配置推理。
4. `Running`：AI持续部署恐龙，守卫全部激活，胜负由现有回合系统驱动。
5. `Ended`：显示地图三专用结算。
6. `LockedReplaySetup`：原布局重试重载场景并重建布局；防御位置锁定，只允许重新选择策略。

这些是地图三协调器的内部阶段，不向共享 `GameState` 枚举增加地图专用状态。共享回合仍使用 `Setup → Running → Ending → Ended`；地图三内部阶段负责细化 `Setup`。

## 5. 防御库存与对象关系

| 类型 | 玩家库存 | 自动附属 | 世界旋转 |
|---|---:|---|---|
| 城墙 | 3 | 每墙1名固定墙上弓箭手 | 长边沿世界 Z 轴 |
| 地面弓箭手 | 5 | 无 | Prefab默认旋转 `0°` |
| 法师 | 3 | 无 | Prefab默认旋转 `0°` |

- 墙上弓箭手不消耗地面弓箭手库存。
- 移除城墙时，其墙上弓箭手同时移除并只返还1面城墙。
- 每个库存实体拥有稳定 token ID；移除后归还同一 token，避免重放快照和观测排序随编辑顺序漂移。
- 完整布局固定为3墙、3墙上弓箭手、5地面弓箭手和3法师，正好填满 v2 的 Walls/Guards 合同，不允许静默截断。

## 6. 防御部署区域

- 使用一个固定世界坐标矩形，所有地图二房屋布局和区域预设共用。
- 矩形围绕村庄，并与任意活动 Z1–Z5 完全不相交。
- 布防阶段始终显示半透明地面填充和清晰边框；战斗开始后隐藏。
- 矩形精确坐标保存于地图三场景配置，不散落在输入、UI或验证代码中。
- 精确坐标必须在实现时基于地图二全部合法 seed/预设量测，生成俯视截图交由用户目视确认后才能冻结；本设计不擅自指定尚未确认的坐标值。

一个候选位置只有同时满足以下条件才合法：

1. 对象完整占地位于固定矩形内。
2. 不与活动 Z1–Z5、房屋、中央目标或其他已放置防御对象实际碰撞重叠。
3. 地面守卫的位置可由其 NavMeshAgent 对应 filter 在小半径内采样回原位置。
4. 城墙使用有效地面命中点，且墙上弓箭手锚点有效。
5. 不增加额外0.5米或1米安全间距；只禁止实际碰撞重叠。

合法性由独立验证器返回结构化失败原因。预览只向玩家显示蓝/红状态，不新增额外错误文本；失败原因保留给测试和诊断日志。

## 7. 玩家布防交互

- 底部横向工具栏包含城墙、弓箭手、法师三张卡片，每张显示图标、名称和剩余数量。
- 点击卡片后进入连续放置模式；预览跟随鼠标，合法为蓝色、非法为红色。
- 成功放置后保持当前类型选中；库存归零或按 `Esc` 时取消。
- 布防阶段右键点击已放置对象将其移除并返还库存。
- 右键城墙或墙上弓箭手均解析到同一墙体组合并整体移除。
- 点击 UI、鼠标没有有效地面命中、位置非法或库存为0时不得产生对象或扣减库存。
- 已放置守卫播放待机动画，但禁用寻路、巡逻、索敌和攻击；开始战斗后统一激活。

## 8. 开战条件与策略选择

### 8.1 策略 UI

底部工具栏右侧常驻三个并列按钮：`PPO`、`FPO`、`ReinFlow`。

- 进入地图三时默认不选择任何策略。
- 可用策略可点击且选中后高亮；不可用或合同不兼容的策略可见但置灰。
- 不使用 PPO 冒充 FPO/ReinFlow，也不回退到随机或启发式策略。
- 原布局重试后策略再次重置为未选择。

### 8.2 开始门

“开始 AI 进攻”只有在以下条件全部成立时启用：

- 城墙剩余0；
- 地面弓箭手剩余0；
- 法师剩余0；
- 已明确选择一个当前可用策略；
- 当前不处于加载、退出或重载事务中。

条件不满足时按钮禁用，并在旁边实时显示缺少内容，例如“还需放置：城墙 1、弓箭手 2；请选择 AI Strategy”。

### 8.3 原地启动与失败关闭

点击开始后不重载场景：

1. 冻结布局快照并停用编辑输入。
2. 隐藏预览和防御区域。
3. 根据选中策略验证并创建对应 Sentis runner。
4. 使用当前房屋/区域/防御实体直接生成六流观测。
5. 原地配置 `DinoInferenceController`，禁用人类恐龙部署输入。
6. 同时激活守卫并启动现有回合。

如果按钮点击后的实际模型加载或合同匹配失败：不启动回合、不改变布防、不计胜负；显示“模型加载失败”，取消策略选择，允许玩家选择其他可用策略。

## 9. AI 进攻合同

- 直接复用地图二对应算法模型；不新增地图三模型 ID 或专用权重。
- 使用确定性推理输出和地图二相同的 inference seed 规则。
- 每25个模拟步产生一次4D动作，经现有 `DinoTrainingActionCodec` 解码并调用 `DinoSpawner.TryDeploy`。
- AI 可选择 Wait；合法/非法部署、肉量、单位上限、房屋奖励和资源耗尽判定均使用现有共享路径。
- 模型输入继续是 Global、Regions、Walls、Guards、Houses、Dinos；玩家自由布防只改变实体位置值，不改变 shape、mask、排序合同或归一化。
- 地图三不加入正式双地图训练采样，除非未来另有明确决策。

## 10. 胜负与退出

地图三从防守方视角展示结果，但共享 `RoundManager.PlayerWon` 当前表示恐龙进攻方是否胜利。地图三通过专用结果投影反转显示，不改变地图一/二现有语义。

- 任意 AI 恐龙进入中央目标范围：进攻方成功，玩家失败。
- 达到50秒：进攻方失败，玩家胜利。
- 场上无恐龙且 AI 肉量 `<25`：进攻方失败，玩家胜利。
- 布防阶段退出：直接返回地图选择，不计胜负。
- 战斗阶段退出：先显示确认；确认后记录手动退出并判定玩家失败，取消则继续战斗。

地图三手动退出必须使用防守方专用的权威结束入口，不能调用当前“恐龙玩家认输”的 `ForfeitSession()` 并得到相反结果。

## 11. 战斗 HUD 与结算 UI

### 11.1 战斗 HUD

战斗期间显示：

- 剩余时间；
- 当前 AI Strategy；
- AI 剩余肉量；
- 存活恐龙数；
- 玩家剩余地面守卫数；
- 玩家剩余城墙数。

### 11.2 结算

结算主体只显示：

- `Victory` / `Defeat`（防守方视角）；
- 本局 AI Strategy；
- 玩家坚持时间。

结算提供三个操作：

1. **原布局重试：** 保存房屋 seed 和防御快照，重载地图三，用相同 seed 重建满生命值布局并锁定；策略重置为未选择。
2. **新布局：** 推导新 seed，重载地图三，按地图二规则生成新房屋并清空布防。
3. **返回地图选择：** 清除地图三临时布局上下文并加载 MapSelect。

原布局重试的布防卡片保留但全部置灰，并显示“原布局已锁定”；只能选择 AI Strategy 和开始战斗。

## 12. 布局快照与重载

`DefenseLayoutSnapshot` 是只包含值的不可变数据，至少记录：

- scene/map stable ID；
- layout seed；
- 配置版本；
- 3个墙 token、位置和固定旋转；
- 5个弓箭手 token与位置；
- 3个法师 token与位置；
- 规范化 canonical text/hash。

快照不保存 GameObject、Component、Transform、NavMeshAgent 或模型 runner 引用。重载时必须重新验证 map/seed/config/hash，并重新走生成与注册路径；任一项不匹配时拒绝“原布局重试”，不得部分恢复或换成新布局。

临时 `DefenseBattleReplayContext` 只在同一应用进程内保存一次待消费快照。返回 MapSelect、新布局、消费成功、场景不匹配或运行时子系统重置时都必须清除。

## 13. 组件职责

### 13.1 新组件

- `DefenseBattlefieldConfig`：库存、固定矩形、墙上弓箭手锚点、Prefab引用和配置版本。
- `DefensePlacementRules`：纯 C# 库存、阶段和快照规则。
- `DefensePlacementValidator`：矩形、碰撞、五区、NavMesh和墙体组合合法性。
- `DefensePlacementController`：鼠标/键盘输入、连续选择、预览、实例生命周期和布局快照。
- `DefenseBattleCoordinator`：地图三阶段、开战门、策略加载、守卫激活、结果投影和事务互斥。
- `DefenseBattleUI`：底部工具栏、状态、HUD、退出确认和地图三结算展示。
- `DefenseBattleReplayContext`：跨重载的一次性值上下文。
- `DefenseBattlefieldLayoutSignatureProvider`：把地图二房屋/区域/目标与玩家防御快照合并为稳定签名。

### 13.2 复用和最小扩展

- `GameMapId`、`MapSelectUI`：增加地图三稳定 ID 与直接入口。
- `LayeredBattlefieldLayoutController`：复用地图二房屋/区域/目标选择；地图三不触发自动防御实例化。
- `EnemyAIController`：只增加地图三防御对象的显式注册/取消注册边界，不接收玩家输入。
- `DinoInferenceController`：增加“已加载场景内显式配置”的安全入口，保留地图一/二自动 bootstrap。
- `RoundManager`：增加防守方手动退出的窄入口和明确 outcome reason，不改变既有地图的 `ForfeitSession()`。
- `RuntimeUI`、`GameResultActionController`：地图一/二行为保持不变；共用的策略可用性解析可提取为小型服务。

## 14. 生命周期与性能约束

- 预览对象不得注册为正式防御实体、不得进入结构化观测、不得运行 AI/动画图或 NavMeshAgent。
- 预览颜色使用独立材质实例或 `MaterialPropertyBlock`，不得污染共享材质。
- 放置检查只在鼠标位置变化或点击时执行，使用复用的 NonAlloc collider buffer，避免每帧分配。
- 所有订阅在 `OnEnable/OnDisable` 或明确初始化/释放中成对处理。
- 模型 runner 创建失败或场景销毁时必须释放；重复点击开始只能执行一次。
- 地图三继续使用地图二预烘焙 NavMesh，不在 episode 内调用 `BuildNavMesh`。动态墙使用现有障碍/目标机制；开始前必须验证至少一条现有攻击流程可处理挡路墙，避免 AI 因无路径永久空转。
- 布防阶段相机与右键移除、中键拖动、左键放置不得相互抢占；UI 上的鼠标事件不得穿透到世界。

## 15. 错误与边界情况

- 缺少配置、Prefab、矩形、五区、目标、房屋、观察构建器、生成器或回合管理器：停留在不可开始状态并记录具体错误。
- 库存为0、UI上点击、非法位置、重复输入、场景卸载中输入：不生成、不扣库存。
- 移除不存在或已锁定对象：无效果。
- 原布局重试快照缺失、版本错误、数量错误、坐标非法或 seed 不匹配：拒绝恢复并返回安全菜单，不静默生成另一布局。
- 策略在 UI 检查后变为不可用：按模型加载失败流程回到布防，不进入 Running。
- `Ended`、退出确认和重载按钮都必须防重复触发。

## 16. 验收标准

### 16.1 纯逻辑

- 库存严格为3墙/5弓/3法；移除正确返还；墙与墙弓箭手原子增删。
- 只有完整库存耗尽且选中可用策略时才可开始。
- 快照 canonical text/hash 对相同 seed、token和坐标稳定；非法或不完整快照拒绝恢复。
- 防守方胜负投影、布防退出和战斗认输语义正确。

### 16.2 场景与部署

- 地图三是独立 Build Settings 场景；MapSelect 第三个按钮直接进入。
- 与地图二相同 seed 时，房屋、目标和Z1–Z5签名一致；地图三自动防御生成器不产生对象。
- 固定防御矩形对地图二所有区域预设均不相交，并获得用户视觉确认。
- 连续放置、蓝红预览、Esc取消、右键移除、库存归还、默认旋转和区域隐藏全部通过 PlayMode 验证。
- 布防阶段守卫只待机；Running 后全部激活。

### 16.3 AI、胜负与重试

- 点击开始不重载场景；当前 scene handle 不变，推理使用选中地图二模型和当前玩家防御观测。
- PPO/FPO/ReinFlow分别按真实模型合同可用/禁用，无回退。
- 加载失败保持布局与 Setup，不创建 runner 泄漏，不计胜负。
- AI保持25步确定性决策、共享动作解码和部署路径。
- 目标进入、50秒、资源耗尽和防守方认输分别产生正确玩家结果。
- 原布局重试重载后布局签名完全一致且锁定；新布局 seed 不同且无防御对象；返回地图清空上下文。

### 16.4 回归边界

- 地图一、地图二的 MapSelect 入口、Human玩法、结算重赛、AI Strategy、退出失败和结果对比测试保持通过。
- v2 六流 shape、4D动作和训练地图选择不加入地图三、不发生变化。
- Unity fresh compile 0个新增错误；聚焦 EditMode/PlayMode 测试全绿；场景 validator 通过。

## 17. 已知风险

- 地图二模型训练时面对预设防御布局；玩家自由布局虽保持相同实体数量和观测合同，仍可能产生分布外位置。用户已明确接受直接复用地图二模型，本任务不以胜率作为功能验收门。
- 独立地图三场景不会自动继承未来地图二的场景改动。validator 必须比较共享房屋/区域规则，后续修改地图二时也应检查地图三。
- 固定矩形精确坐标仍需实现期场景量测和用户目视冻结；除此之外，本设计的玩法与技术选择均已确定。
